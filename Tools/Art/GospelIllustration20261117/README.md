# SharpIllustration world-character candidate

These are source-only candidate generators. Root executes asset preparation and all Unity, motion, Native, Web and visual checks. They do not provide a verified aesthetic result or AAA equivalence.

The baseline remains the retained, licensed ActorBake09 FBX set, face geometry, morphs, textures, Humanoid Avatar and seven motion clips. No extracted commercial-game asset or paid kit is used. The new output is compact derived mesh/material data, not another full FBX/texture set.

## Concrete geometry changes

`GospelIllustrationTailoring.Apply(instance, actorIdentity)` operates on a fresh, unanimated Editor instance after its original Avatar/controller are assigned. V5 retains the original connected neckline/torso/sleeves through exact source-cloth extraction, restores the boy's exact source knee-free tunic/hem geometry, fits open-front outer cloth outside the real torso envelope, and gives Mary/Teacher a dedicated rounded hood dome and fall. Synthesized outer cloth uses only existing Humanoid transforms with at most four normalized influences; extracted source clothing preserves every original variable influence and the original rendering SkinQuality.

JesusChild alone receives an eye-clearance hair mesh from `GospelIllustrationHairline.BuildEyeClearance`. It derives its mask from the actual eye bones and raises only a smooth bounded central-front fringe region. Original hair geometry is retained in its original FBX; UVs, topology, submeshes, weights and bindposes are copied into the new candidate. It does not invent a new face or remove source facial morphs.

New v5 mesh/material outputs live under `Assets/Art/GospelIllustration20261117/v5/<actor>/`. The earlier v1/v2/v3/v4 outputs remain unchanged. These folders are outside Resources, and only the stable existing character prefabs reference the selected version. A previous differing derived mesh is preserved and causes preparation to stop; change the versioned output root after review rather than overwrite it. Original FBX, model .meta/GUID, source textures and source manifest are not rewritten. Generated materials retain each actor's current ivory/teal, ivory/rust, muted blue, sand/brown or ivory/sage palette.

## V5 source lower-tunic restoration

Root's actual Proto04 found a large thigh penetration during the child's walk/run. The previous child-only lower garment transformation extended the old hem from above the knee to below it and narrowed width/depth while retaining old leg/calf weights. Those changes did not match the original source hem, rest envelope and retained knee skin. V5 removes that deformation rather than altering the original body or skinning tolerance. The original TailoredTunic and WovenHem Mesh pointers, original positions/normals/UVs, hem/width/depth, complete weights and bindposes remain exact. Only the tunic renderer uses the improved derived Linen material; the woven hem keeps its original palette. No new lower garment geometry is generated, and the old reshaping helper is removed.

The per-actor report explicitly marks original child lower geometry retained and identifies both meshes as source geometry. A narrow protection branch checks that their original mesh/bone/root references are unchanged, allowing only the tunic's derived material. Hair, fitted upper shirt geometry, adult open-front shawls and hood geometry remain unchanged. Actual walking/running is still required before claiming the penetration is resolved. Mary's original lower garment is not changed by this child-only correction; its existing motion slits remain a separate observed limitation.

V5 also supplies a separate `IllustrationFittedLinen.mat` for the four extracted source shirts, using the optional `openSourceCloth` material-factory parameter. Its opaque shader omits the inverted-hull outline, since the source shirt is a single open neck/sleeve surface. Closed garment materials, tunic/mantle outlines and every skin/face/hair setting remain unchanged. This is a narrow A/B for the observed dark neck/shoulder fragments, not a verified cause or fix. Actual Proto05 must establish whether those fragments improve; no original material or earlier version is modified.

## V3 after Root's actual V2 visual rejection

Root rejected V2's oversized shoulder/chest cap, intersecting underarms, angular crown and Mary's drape hidden inside her white clothing. That prototype is retained and has no visual approval. V3 stops generating the cap and independent sleeve rings. `GospelIllustrationFittedCloth` separates only the exact `id__UndyedLinen` Body draw triangles into a fitted shirt, retaining its original connected triangle topology, UVs, authored normals/tangents, complete BoneWeight1 palette and bindposes. The shirt clones the complete original vertex/skin buffers and draws only the selected cloth index array. Only cloth-referenced positions receive 1.8mm of actor-scale normal clearance; every unused position remains exactly original and no unused triangle is drawn. The original source Body remains unchanged; a new Body remainder contains every original vertex payload and every anatomical/other triangle, emptying only the cloth draw slot now rendered by the shirt. This is one verified triangle partition, not anatomical body hiding.

The sole new Body-pointer exception is limited to JesusChild/JesusAdult/Joseph/Teacher and requires exact partition/payload/skin-weights/bindpose/quality proof. The fitted shirt uses the original Body renderer frame, full bone palette, root bone and SkinQuality. Native per-vertex influence sets are cloned and checked without truncating them to the four-weight legacy view. Actual Prepare09 rejected an initial compacting candidate because Unity's `SetBoneWeights` re-encoded the copied values. The repaired helper does not call `SetBoneWeights` or compact any vertex buffer; exact full native influence count/order/index/value checks remain. That failure occurred before the fitted shirt/remainder were persisted. Existing v3 tunic/hem/fringe outputs are preserved and may be reused only under the existing exact matching rule. Source model fingerprints and the fresh-source rest checks remain exact.

Outer drapes now enclose directional support distances measured from the real torso points; Mary's data additionally includes a temporary actual-skinned TailoredTunic sample. The outer surface has 18mm actor-scale clearance before thickness/folds, and the drape follows only torso weights. The hood reserves 24 intervals for its analytic scalp dome and 24 for its lower fall, rather than allocating only five or six rows to the crown. New v3-only garment materials use a restrained cooler shadow color (.58,.64,.76), strength .86 and environment return .04; face, hair, global sunlight and ambient settings are unchanged.

Root must inspect the real shirt/armhole connection, skin/cloth partition, new drape clearance and dome, then repeat actual walking/running/head turns. No new source authoring establishes that this prototype looks acceptable. The selected v9 actor manifest explicitly omits previously rejected beard geometry for JesusAdult/Joseph/Teacher; old JawBeard material files are retained but are not a hidden usable beard mesh. The clean-shaven world/bearded illustration distinction remains unresolved by this geometry repair.

## v2 source-rest and persisted-name correction

Root's actual RigDiagnostic01 found that all five fresh instances match their imported source transforms. The four C-derived actors have no original bind-palette identity failures; Mary has 1,102 nonidentity entries across her original renderer palettes, including 43 entries with actual positive skin influences. An identity-only test therefore cannot describe Mary's legitimate imported source rest. V2 retains the `.004` identity requirement for the other four actors and for every newly generated garment bind-pose round trip. It does not change or rebind Mary's original skin.

Before changing any clothing, v2 loads the exact FBX containing the actor's Avatar and compares the original instance hierarchy, exact local TRS components, mesh/material references, bone palette paths/order, root bones and default morph weights against that imported source. It rejects a sampled animation or modified instance. For Mary only, the Body/Hair/Face dimensions are read from temporary `BakeMesh(false)` results in renderer-local space, then transformed into actor-local space. Vertex correspondence, finite coordinates and nondegenerate extents are checked; the temporary meshes are destroyed. The source-rest comparison and exact original mesh fingerprint are checked again after sampling. No baked mesh is assigned to an original renderer or saved as a replacement original skin.

The per-actor preparation report records source-rest model/transform/renderer proof, original nonidentity and positively weighted entry counts, maximum identity error, the sampled-envelope flag, and actual sampled extents/displacement. These facts do not establish animation clearance: new garments and the original skin can blend differently, so actual idle/walk/run/head-turn inspection remains required.

RigDiagnostic01 also found identical child UpperTunic geometry/weights/bindposes but a different mesh name: Unity saved the asset with its file stem, while the candidate added `Mesh` to that name. V2 uses the exact renderer/file-stem name before fingerprinting. Exact original-mesh protection and exact persisted candidate matching remain in place; no geometry epsilon or hash relaxation is introduced. Root's diagnostic output and v1 artifacts are preserved as prior evidence. V2 source still requires actual preparation, a repeat preparation to check reuse, and new visual/motion validation.

## Actual source-bound expressions

`generate_expression_bindings.py` validates all five retained actors and exact mesh/morph names in `Tools/Art/GospelNpr/actor-manifest.json`. Its small `ExpressionBindings.json` provides ih, oh, relaxed, sad and happy presets. C-derived source names i/o/fun/sorrow/joy are normalized as metadata; Mary uses her actual source names. Runtime resolves names rather than guessed indices and applies low transient weights with onset/release easing. Existing blink and mouth-A bindings remain.

`GospelNprCharacterView` supports `SetSpeaking(bool, storyVoiceKey)` and explicit `SetExpressionCue`. Mary at `parents-reunite` uses restrained concern; `nazareth-return`/`pilgrim-spring` use gentle attention; the two existing good-news/witness prologue keys use restrained joy. Other beats use attentive expression. Cues are transient presentation and never enter a save. A/I/O syllable envelopes include closed-mouth pauses and make no audio phoneme-sync claim.

`HasSourceExpressionMap`, `ExpressionBindingCount` and `CurrentExpression` expose actual binding state for meaningful checks. The old 3D portrait backend remains for world/rig/lifecycle regression checks; the separate UI owner replaces HUD/status/dialogue with illustrated portraits.
