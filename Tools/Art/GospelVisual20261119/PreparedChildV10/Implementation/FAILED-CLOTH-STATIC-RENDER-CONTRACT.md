# Failed static cloth diagnostic — source only

`render-failed-cloth-static-v1.py` is an unexecuted Blender4.3 source proposal. Root alone supplies actual failed inputs and runs it. It never treats a failed sewing result as a final character, quality pass, Unity render or shipping approval.

```text
blender --background --factory-startup --python-exit-code 2 --python /ABS/render-failed-cloth-static-v1.py -- --blend /ABS/JesusChild-Hinzka-Sewn-v8-FAILED-PREWELD.blend --blend-sha256 EXACT_SHA --failure-report /ABS/cloth-failure.json --failure-report-sha256 EXACT_SHA --baker-source /ABS/bake-hinzka-child-v8.py --baker-source-sha256 EXACT_SHA --output-root /ABS/NEW-static-failure-render [--source /ABS/original.vrm] [--threads 4]
```

Every input path is absolute, regular, nonsymlink and byte-pinned; the failure report must pin that exact saved blend. Output must be new, with an existing parent; no overwrite or source `.blend` save occurs. `--source` optionally checks the exact original VRM. Without it, the source SHA guard explicitly identifies the retained byte-exact `source.glb` beside the failure report, not an unobserved original file. Expected source SHA is `7526838f4a45086a1d0abb23e9f38ad3f0103889f1efa70d2605ef25e7e6ef99`.

The renderer loads actual object datablocks using `bpy.data.libraries.load` into a fresh empty scene **without importing/evaluating the failed Scene**. Every Cloth modifier is disabled before any object is linked into a depsgraph. Only the unique guarded artist face/body/hair, original rig/ancestors, and exact `FAILED_NOT_APPROVED__ActualPreweldCloth` / `FAILED_NOT_APPROVED__ActualPreweldMesh` are linked. Original derived cloth is hidden. The required frozen mesh has no modifiers or morphs and must match the real failure's frame, native counts, UV layers, materials and world matrix. It does not depend on a missing RAM point cache.

There are no `frame_set`, point-cache, simulation, cloth reevaluation, pose changes, mesh/UV edits, actor material edits or blend-save calls. The pinned V8 module's exact `geometry_hash`/`rig_hash` definitions are loaded under a non-main `ModuleType`; no `main()` runs. `sourceAfterBlendSave.actual` must match before/after every render. Additional snapshot native/world-point SHA, native pose-channel SHA, material graph/image SHA and blend/report/baker/source file byte guards remain unchanged. Actor source animation is rejected rather than re-timed. Only new camera/lights/world and render/color settings are created; no replacement floor, anatomy or beauty deformation is added.

Six actual CPU Cycles32 PNGs are requested: front/quarter/side × fullbody1280²/face1024². Denoising/preview denoising are off; no OIDN render is requested. `--threads` is1–8 (default4). Orthographic framing comes from actual referenced native/frozen world vertices; nonfinite/empty geometry or a span≥10m fails honestly. Root must bound the actual subprocess externally; Python cannot interrupt a blocking Cycles render. Source-material appearance (including original UNLIT graphs) is retained and is not claimed equivalent to Unity/toon presentation.

Each PNG gets actual SHA/frame metadata; the final report and all filenames prominently retain `FAILED_NOT_APPROVED`. Partial outputs remain on any error. A completed diagnostic only means the static render sequence and source guards completed. Root must still inspect the actual originals, sewing failure, pin/neck/body intersections and later successful cloth/model/Unity results independently. This author read source text only and did not execute/import/read any actual model, image, failed report, state or cache.
