# Fresh child preparation API

`Editor/GospelHeroChildPreparation.cs` is an independent Editor source entry point. It imports a **new**, already authored/baked child FBX and its pinned source images into a fresh version under `Assets/Art/GospelVisualRebuild20261119/`. It does not call sample-C `bake_actors_v9`, face refinement, head growth, procedural beard, old neckline or old periodic robe helpers. It does not modify the original selected VRM or replace the four other roles.

Root supplied the actual selected original VRM SHA `7526838f4a45086a1d0abb23e9f38ad3f0103889f1efa70d2605ef25e7e6ef99`, 109 native bones, face 122 non-Basis morphs, native Fcl blink/A/I/O and a child-appropriate unwarped appearance. The source author did not inspect that binary or a rendered preview. The exact source license/entitlement and derived asset admission remain Root's responsibility; this code does not infer rights from embedded metadata or override a recorded license conflict.

## Entry point and outputs

Root may call `GospelHeroChildPreparation.Prepare(Settings settings)` directly or set `FIRSTGAME_HERO_CHILD_SETTINGS` to the exact config JSON path and invoke `Firstgame.GospelNpr.Editor.GospelHeroChildPreparation.PrepareFromEnvironment`. `FIRSTGAME_HERO_CHILD_REPORT`, if set, is a **new** report path written with CreateNew. No report is invented before the actual call.

The config is `JsonUtility` field JSON matching the public `Settings`/nested types. All paths in `FilePin.file` are exact readable local files, and each has its exact `bytes` and lowercase SHA256. No input path is implicitly guessed from an earlier attempt.

- `schema=1`, `actorId="JesusChild"`, `sourceSha256` equal to the pin above.
- `originalVrm`: exact original VRM FilePin. `model`: exact newly baked FBX FilePin. Both are verified before/after; source images are copied byte-for-byte.
- `outputVersion`: fresh letters/digits/underscore/hyphen token. Existing output directory/meta or already activated new child prefab causes failure. Preserve the attempt and explicitly review activation/versioning before replacing anything in a later attempt.
- `controllerAsset`: actual existing seven-motion humanoid AnimatorController asset. It must expose MoveSpeed float, Grounded bool and VerticalSpeed float. Controller/motion source assets are referenced rather than overwritten.
- `nativeBoneNames`: all 109 actual source/native bone names, unique. `humanBones`: normalized Unity semantic/boneName pairs from the source VRM humanoid map. VRM thumb semantics must be normalized correctly for that format; do not guess indices. All native secondary hair bones stay present even when not Humanoid mapped.
- `faceRenderer`: exact exported/imported renderer object name. `faceMorphNames`: all 122 actual non-Basis names. The importer accepts an FBX channel prefix only through exact `"." + originalName` suffix matching, not guessed positional indices.
- `maximumExportedInfluences`: actual maximum after new cloth/export, including all derived garment influences. It must be 1–32; the importer is custom32/minimum0 with Unlimited runtime skin weights required. Imported maximum, normalized sums and complete native streams are checked. This is not a per-vertex proof of exact FBX weight retention; fresh actual functional/native source validation must still inspect geometry/weights, bind poses and motion meaningfully.
- `axesVerified=false` by default: the preparer first imports and verifies actual head/eye geometry faces Unity+Z, head/hips are upright and actor transform +Y/+Z agrees with that frame. It then derives and records head-local forward/up from that verified frame. No pre-import basis guess is required. If independently measured axes already exist, set `axesVerified=true` and provide `verifiedHeadLocalForward` / `verifiedHeadLocalUp`; they are compared within .5° to the actual imported result. Do not copy Blender axis values into Unity local fields.

`textures[]`: `key`, `source` FilePin, `normal`, `data`, `alpha`, `maximumSize`. Source images must be raw extracted PNG/JPEG bytes with recorded origins. Data maps import linear, Clamp, uncompressed and alpha-is-transparency false. Color images retain their pixels/alpha; importer settings change only new copies. Different keys must also have distinct sanitized output names.

`materials[]`: exact `sourceName`, explicit factory `role`, optional `textureKey`, source linear `color[4]`, `hsvg[4]`, explicitly recorded `artisticTintSrgb[4]`, `alphaMode`, `cutoff`, `doubleSided`, `uvScale[2]`, `uvOffset[2]`, `uvChannel`, `uvRotation`. UV0 only/no rotation is required unless the export already baked those transforms; unsupported source texture transforms fail instead of disappearing. Use source color separately from a documented new brown-hair tint. Original hair geometry/morphs and PNG pixels remain unchanged.

Each material has `heroSurface="Legacy"` by default. Opt into exactly `Face`, `Eyes` or `Hair` only after source review. Source BLEND always remains legacy, and unverified eyes remain legacy. This preserves smooth-alpha iris edges and highlight-only planes. For fitted OPAQUE/MASK eyes set `fittedEyeVerified=true` and the explicit `eyeSurface`; MASK cutoff is retained. Hair strand flow is selected per material with `hairFlow` 0/U, 1/V or 2/authored UV vector and `hairUvFlow`. The source's own hair UV layout is not assumed to match the old added locks.

`expressions[]`: exact `preset`, `renderer`, `shapeKey`, normalized `weight` `(0,1]`. At minimum supply `ih`, `oh`, `relaxed`, `sad`, `happy` from actual source VRM group/target data. The basic Blink/A path still uses the existing View's actual Fcl aliases. Validate source weights and combined expressions in the new model; do not infer good speech from morph count alone. Multiple shape bindings for one semantic group are allowed if each resolves uniquely.

## SDF fallback and activation

Default `enableGeometryFaceSdf=false`. Face surfaces use the new face shader's normal-based fallback; the preparation report records SDF false. The model is not blocked waiting for an invented or generic mask.

To enable geometry-baked data, provide `faceSdfTextureKey`, `geometryFaceSdfCompatibilityVerified=true` and pinned `geometryFaceSdfReport` FilePin. Its JSON must have `shaderCompatible=true`, the exact `sourceSha256`, `dataPngSha256` matching that texture's exact bytes, and a nonempty `contractSha256`. Inspect-only/incompatible reports cannot enable SDF. The geometry baker separately verifies its actual UV mirror/axes/occlusion contract; its output is **geometry-derived angular shadow data**, not artist-painted signed-distance art.

The new prefab path is `Assets/Resources/Art/GospelHero20261119/Characters/JesusChild.prefab`. It contains `GospelHeroModelProfile` with exact source/FBX hashes, authored height1.42 and its own generated expression TextAsset. Apply the combined View patch or full replacement source exactly once. It first resolves the new child profile and otherwise uses the old resource root. A present but malformed new profile fails visibly instead of silently falling back. Other actors and old expression catalog remain intact. World and clone portrait use the same selected prefab and its expression mapping; the clone permits only the head-frame binder behavior.

The imported model must already be height1.42, feet0 and face Unity+Z. The Editor does not resculpt, regrow a head or disguise a facing/scale problem. It preserves original 109 bone identities and all 122 shapes, validates the new humanoid Avatar and controller, and reports preparation only. The old human smoke assertions about exact sample-C assets stay applicable to their historical/sample path; they are not repurposed as a claim that the new model has the old source. New actual Native tests must cover admitted-source hashes, 122 expression names, live mouth/blink, complete rig/native skin, locomotion/feet/cloth, portrait, save/story IDs and shader/material role/alpha behavior.
