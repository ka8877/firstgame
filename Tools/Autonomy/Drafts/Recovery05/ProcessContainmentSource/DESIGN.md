# Owned descendant containment — source-only successor

This draft is uninstalled and unexecuted. No live process query, signal, module import, Unity, network or Git operation was performed by its authors. Original a6bc caller, failed CardWeb01 evidence and later natural termination remain historical facts. A late successful BuildEvidence cannot turn the timed-out caller into success.

Each actual command gets a new dedicated supervisor. It has no children before launch, normalizes SIGCHLD, enables and verifies PR_SET_CHILD_SUBREAPER, and launches exactly one root command. Its kernel descendants remain in this subtree across setsid and doublefork. An orphan is adopted by this living subreaper. A preexisting licensing client, unrelated session or IPC service never becomes owned merely because it looks new or has a similar command name.

Admission requires a current kernel parent edge to this supervisor or a still-live pidfd-anchored owned parent, and matching startTicks/UID around pidfd_open. The initial global identity snapshot is exclusion evidence. Signals use pidfd only after current UID/startTicks and held pidfd identity checks; there is no numeric-PID or process-group fallback. Changed UID, unknown lineage, permissions or missing identity are blocked observations. A zombie leader is not assumed to mean the entire process exited; pidfd readability and kernel waits determine exit.

A single coordinator peeks waitid(P_ALL, WEXITED|WNOHANG|WNOWAIT|__WALL) without consuming status, then reaps only that exact known child. The original root has one exact-PID waitpid owner; Popen.poll/wait never competes. Optional /proc/.../children is not required, and an empty PPID scan is never the completion proof. Root exit0 is separate from cleanup. Completion requires the living verified subreaper to reap until kernel ECHILD, no live held pidfd, no unknown living owned child and no unresolved ownership error. A /proc scan or empty original PGID is insufficient. ECHILD is stable because this dedicated supervisor launches no further root commands.

The existing shared900-second safeEnd and lease−60 boundary include productive work and owned-child cleanup. The command deadline is min(now+caseCap, sharedSafeEnd−12): cleanup10 and outer reporting2 are reserved before spawn. With≤12 seconds remaining no command is started; a small isolated case cap is not reduced by12 when its common envelope is large enough. Failure-state metadata keeps the original separate60-second reserve. Normal root exit, timeout, interrupt or parent death switches the supervisor to bounded cleanup: continue discovering owned descendants, request TERM through verified pidfds, then KILL only those same proven identities. Failure to prove empty remains pending/false. Kernel D-state, privilege changes, missing receipt or an externally killed supervisor cannot be converted into success. Cancellation takes outcome130 precedence even if timeout was observed first; both raw facts remain in the receipt and neither can become success.

The outer caller requests supervisor cancellation and waits for its cleanup receipt. It must never kill the supervisor PGID at the execution deadline, which would remove the subreaper while descendants still live. It verifies the supervisor's actual result and ECHILD proof. If the supervisor itself misses the bounded cleanup/report deadline, the caller records containment unproven and retains its exact identity; it does not claim idle, restore source, retry or extend execution. PR_SET_PDEATHSIG requests cleanup if the outer caller dies. An independent preexisting broker launching work by IPC is outside kernel-descendant ownership: such unattributed Unity activity blocks the caller and is never guessed as a kill target.

Production enablement requires a byte-bound actual isolated test report, independent source audit and sole operator acceptance for this exact helper/fixture/test-runner source set. The draft contracts leave these acceptance references null, so no production command can run from this draft. Required tests use Python dummy descendants only: normal exit, nonzero exit, setsid timeout, doublefork timeout, doublefork with root exit, caller interruption, unrelated preexisting bystander, and stale-identity/UID refusal. The fixtures must establish their escape before cleanup; preventing the fork does not count as exercising it. Stale identity tests are explicitly simulated metadata mismatches against a real owned dummy, not claims that the host reused a PID.

The Card successor uses fresh Recovery05/WebRuns/CardWeb02 and /tmp/firstgame-c1-recovery05-cardweb02-builds. CardWeb01/R4 outputs and actual held a6bc tool are never resumed or overwritten. Only the verified compiler cache may be reused by the actual owner. Native8/Root/source9 and all product/source/restore/proof/false-readiness gates remain unchanged. Gospel V2 has the same old Lane risk; its follow-up patch is source-only and also requires this tool acceptance proof plus an owner-selected future batch and the existing Gospel Root static review. Native6fb and actual Native source inputs are not patched.

The extra Root-labelled tool-test review in the first concept was a draft design choice, not an inherited project requirement. The successor uses the authorized sole operator’s actual test acceptance and a separate independent source audit. It never substitutes these for existing Native, Gospel static, browser/public or final paired Root gates. PIDfd pins a process identity, not an atomic UID condition across credential-changing hostile code; the source and tests cover the current non-hostile same-UID build flow and reject observed UID/identity changes.
