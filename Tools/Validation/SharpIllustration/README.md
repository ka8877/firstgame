# Sharp/Illustration release source contract

This new profile selects both current games: `fm-sharp-client-2026-11-17` and `gospel-illustrated-anime-2026-11-17`. Historical selectors, contracts, evidence and passes remain unchanged. `release_profiles.py` delegates old names to their original selector and defines only the new profile itself.

Current roots default to `Artifacts/Validation/SharpIllustration-2026-11-17`, its matching Autonomy control, `/tmp/firstgame-sharp-illustration-20261117-builds`, and `Artifacts/SharpIllustrationWebPlaytest`. Proof originals remain in the regular persistent control's BuildProof tree. Root owns actual independent ownership, preparation, imports, all execution, source review, assets, Native/Web/browser results, and publication.

The baseline stores source obligations from the previous current Card11/Gospel17 selection and all previous three-profile routes. One explicit UI representation replacement is legitimate: the old story UI test requiring a 3D RenderTexture is replaced by `GospelIllustratedSpeakerSmokeTests.IllustratedMarySpeakerSurvivesBibleAndActualReloadWithoutMovingPhysicalStory`. That case checks the actual Mary illustration, exact speaker/line, nonblank image and aspect crop, unchanged real opening/physical traveler, Bible return, actual saved-slot reload and absence of editorial metadata. All sixteen other Gospel cases remain, including real skins/animation/feet, backend same-model portrait lifecycle, occlusion, two-person Mary composition and every story/passage. The mouth check samples a complete real speech cycle and retains the actual >3 morph/vertex-deformation threshold, restricted to mouth channels so a blink cannot satisfy it. A new additive case requires all five actual world actors' source maps, live A/I/O renderer-weight changes over real nonzero authored vertex deltas, stopped-mouth closure and unchanged physical owners. The resulting source selection is Card11/Gospel18. The Card case keeps all static bitmap Hangul/Jamo/catalog/TTF-exclusion coverage while checking that the actual live client now renders the requested Korean SDF font and visible glyph geometry.

All six full browser suites retain their existing ordinary input, every previous checkpoint, four actual audio windows, two continued-save reloads, source/runtime identity and direct Root image review. New sharp-client and illustrated-speaker/HUD originals are additive. Old same-model wording is changed only where it described the actual speaker UI, which now intentionally uses illustrations. World-model checks remain three dimensional.

Desktop uses an actual DPR1 browser context; mobile and public use actual DPR2 contexts for each game. The new profile must observe the shipping DOM canvas, CSS size, backing dimensions, real browser DPR and existing WebGL drawing buffer after initial boot, both full reloads and every required original. The buffer must honor full CSS×DPR, including touch. A DPR2 screenshot or a configured quality value cannot excuse a lower-resolution canvas. Root's original-image review remains necessary for visual clarity and character/art quality. Software Chromium is not physical-device performance or user aesthetic approval.

`harness-integration.patch` retains the bounded authoring proposal that is now applied to the shared harness; it is not an executable helper or an instruction to apply it again. The current canonical harness and separately captured `clarity.py` are the execution sources.

Native selection and all plans remain **draft** until Root reviews the actual final test sources, current ordinary-input geometry and new portrait assets, then explicitly freezes the source contracts. Zero source pins are deliberate draft placeholders, never claimed source identities. No old pass or Root mark is copied as current approval. The frozen baseline may not be weakened to make a new run pass.

The source-only fourteen-case synthetic unit suite covers rejection of low-resolution buffers despite high DPR metadata, the former 1.25 touch cap, wrong context/canvas, missing reload/checkpoint observations, mislabelled checkpoint observations, absent explicit canvas matching and invalid dimensions. Root alone executes it and all product checks. Authored source is not a test pass.

The optional Sharp-only stager flag `--hardlink-current-proof-core` shares exactly the current independently copied proof Runtime index and four Build files per game with a new stage on the same filesystem. It validates actual source/build SHA and bytes, retains original source inodes, and records source link-count/ctime changes plus each new immutable alias in the new generated-stage ledger. All browser/build/readiness/budget/full-stage checks still apply. No index is rewritten after linking. The flag is rejected for historical profiles; without it their original copy behavior stays unchanged. No hero, notice or media link policy is added beyond the existing Card JPG behavior. Every linked proof/stage alias must remain immutable, including content, chmod and utime.

The separate Sharp-only option `--hardlink-current-gallery` avoids a cross-filesystem JPEG copy from the fresh temporary build. It binds all 15,350 exact `StreamingAssets/Cards/fm_<numeric-id>.jpg` names to fresh media verification, the current proof/BuildInputs and actual equal source/build bytes, then creates fresh stage aliases from retained original `Games/FantasyCards/Assets/StreamingAssets/Cards/` images. Existing source inode aliases are accounted in groups; each new stage target adds exactly one link. The separately captured `stage_gallery_storage.py` uses one complete before-plan ledger and one terminal complete/failure ledger, without rewriting a growing 15,350-row JSON for every image. Source pixels, modes, mtime, inode and existing pathnames remain unchanged; nlink/ctime changes are explicit. It never replaces a source or target and never automatically cleans up a partial attempt. All full-stage/current build/browser/budget checks remain required. Both optional flags are rejected for historical modes. No new hero or notice links are introduced.

Fresh Native invocations capture the central registry as well as any delegated legacy selector, and current Web admission checks both exact source snapshots. Historical records remain unchanged; no old validation is relabeled as current. New illustrated-image notice and source-manifest copies are required only for the Gospel Sharp stage.

`root-review-helper.py GAME PROFILE ATTEMPT status|mark|reply|finalize` keeps the previous explicit Root bookkeeping semantics under the new roots/revisions. It never views an image itself or marks names automatically. Root must personally inspect each named actual original before `mark`; `reply` accepts only bounded ordinary actions for one current request; `finalize` requires the complete actual wrapper, exact untouched executed report and every required explicit Root mark. It also calls current Sharp plan admission, so a draft source/route cannot enter through this helper. These are review records, not automatic source, image or publication approval.
