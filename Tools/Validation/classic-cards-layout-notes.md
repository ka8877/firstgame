# 클래식 카드 UI 검증 좌표

현재 `FantasyCardsApp`의 Unity anchor 기준이다. 모든 값은 실제 맞춤 canvas 안의 0..1 좌표이며 웹 페이지 전체 viewport 좌표가 아니다. Unity y는 아래에서 위로 증가한다. **포인터/OCR 도구의 위→아래 y는 `1 - unityY`** 로 변환한다. canvas의 left/top/width/height를 먼저 읽고 이 값에 곱한다. 아래 표의 `pointer(x,y)`는 이미 위→아래로 바꾼 중심점이다.

`Compact`는 canvas width < 1400 또는 width/height > 1.95다. 따라서 1280×720과 모바일 가로 화면은 compact, 1920×1080은 확장 화면이다. 모바일 viewport 844×390이면 실제 16:9 canvas는 약694×390으로 좌우에 여백이 생길 수 있다. viewport의 844를 그대로 곱하지 않는다.

필터는 **팝업 옵션 선택 방식**이다. 옵션 위치 index=`enum값+1`이며 index0은 전체. `col=index%4`, `row=index/4`로 `pointer(.16 + col*.226, .2975 + row*.145)`. 선택하면 바로 도감으로 복귀한다. 종류 enum: 지형0/유닛1/마법2/장비3. 속성 enum: 빛0/물1/불2/숲3/금속4/대지5/암흑6. 소울 옵션 value0..7 및8(8이상). 등급 순서: 프리/커먼/언커먼/레어/스페셜/업그레이드/유니크/이벤트/레전드/아이카젠/시크릿/에픽. 실제 선택 카드에 없는 등급도 필터할 수 있고 이 경우 `이 조건에 맞는 카드가 없습니다.`와 `필터 초기화` 표시. 팝업 돌아가기 pointer(.5,.915).

카드 상세: `돌아가기` pointer(.67,.87), `원본 카드` pointer(.885,.87). 카드 규칙 설명 영역 anchors(.55,.23,.96,.415)은 긴 설명을 위한 실제 세로 ScrollRect다. 원본 카드 화면은 `능력 설명` pointer(.5,.915)로 상세 복귀. 원본 전체 이미지 아래에 DB/인쇄 수치 버전차이 안내가 있다. 원본 화면에서 곧바로 도감으로 돌아가는 동작이 아니라 상세→돌아가기 순서다.

덱 분석: 0~7/8+ 소울 막대, 항목 GO=`Cost bucket <n>` 자식 TMP=`Count`, `Cost`. 유효성 결과는 실제 `DemoCatalog.ValidatePlayableDeck` 메시지다. 돌아가기 pointer(.5,.915).

전열 GO `Lane <owner> <index>`(owner0=나/1=상대). 선택 카드와 실제 Core.CanPlay에 맞는 칸만 강조된다. 비어 있는 상대 칸은 클릭해도 공격하지 않는다. **수동 공격자·대상·가로막기 조작은 없다.** 양측 준비 완료 후 자동 공방하며 UI 이벤트를 재생하는 동안 버튼 비활성이다. 상대 예약 마법은 앞면/이름을 공개하지 않는다. 내 예약 마법은 앞면과 `마법 예약 · Lv n`이 표시된다.

중앙 상태/OCR: anchors(.025,.475,.975,.598)의 왼쪽 부분, Unity y(.5365..594) 정도. `공격 준비`, `방어 준비`, `전투 판정 중`, 저장 메시지를 확인한다. 내 자원 한줄은 anchors(.025,.270,.975,.318): 덱/손패/LP/색소울/총소울/지형 수. 상대 정보는 anchors(.025,.755,.975,.872).

손패 viewport: anchors(.18,.022,.98,.255), 위→아래 y(.745..978). 6장 이상일 때 실제 가로 ScrollRect. compact의 카드 간격은 canvas width*.16, 카드폭은 *.152다. 초기 scroll0에서 카드 중심 x=.256+i*.16 (6번째는 오른쪽 밖). 실제 마우스/터치 드래그로 오른쪽 카드를 볼 수 있다. 확장 화면의 간격은 *.133이라 6장 거의 전부 표시된다. 5장 이하는 화면 중앙에 직접배치되며 중심 x=.59 - count*width/2 + i*width + (width-.008)/2, width=min(.16,.79/count). 카드 GO `Card <stableId>`.

각 준비 단계에서 **카드 사용 전 손패 전체 셔플 1회**가 가능하다. 시작 손패 교체도 첫 준비의 셔플 허용분을 쓴다. 카드를 사용했거나 이미 섞었으면 `손패 셔플` 비활성. 저장과 전체reload/이어하기는 `fantasy-battle-classic-v3` 슬롯을 사용하고 이전 `fantasy-battle-demo-v2`는 유지한다. 새 저장버전은 Core가 관리한다.

## 검증 주의

실제 화면/OCR과 입력으로 진행한다. HTML DOM의 canvas가 로드됐다는 이유만으로 게임 상태를 통과시키지 않는다. 랜덤 손패에 지형/유닛이 없을 수 있으므로 보이는 실제 카드로 선택하고 필요하면 합법적인 손패 셔플/준비 완료를 사용한다. 원작 코인 결과나 상대 손패를 런타임 인젝션으로 읽지 않는다. 다른 viewport에서 잘린 카드와 아직 로드 중인 글자를 성공으로 가정하지 않는다.
