# 판마 싱글 수집 여정과 상점

`fm-quest-2026-10-30`은 기존 전투·카드 원본과 별도로 실제 보유 카드와 SP 잔액을 갖는 로컬 싱글 수집 경로를 추가한다. 기존 무료 연습은 이전처럼 모든 연습 덱을 시험할 수 있다. 수집전과 시나리오에서는 실제 보유 수량을 만족하는 50장 덱만 사용한다. 유료 결제는 구현하지 않으며 GP는 항상0이다.

## 원작에서 확인한 것과 이번 구성

2016-11-10 제오닉스 관련 [Inven 기사](https://www.inven.co.kr/webzine/news/?news=167189)는 ‘게임캐시(3만GP)’와 ‘게임머니(300만SP)’, 하루에 한 번 구매하는 ‘어드밴스 무료 부스터 A/B/C’를 명시한다. SP와 GP의 이름·역할 및 무료 부스터의 존재는 이 근거를 사용한다. 원문·조사 기록은 `Tools/Research/Quest`와 [이번 조사](Research/QuestReferences.md)를 따른다.

아래 환영 보상, 싱글 승리 보상, 상품 가격, 확률, A/B/C의 유닛·기술·지형 구분, 하루 셋 중 하나라는 공유 한도, 기존27개 덱 중 일곱 단일속성 덱의 첫 선택 구성은 **이번 싱글판의 재구성**이다. 종료 직전 서버의 경제 데이터·원본 초기 덱·유료 상품이나 확률표를 복구한 것으로 소개하지 않는다. 무료 부스터와 일일 목표의 날짜는 한국 시간(`Asia/Seoul`, UTC+9)이며 UI가 현재 날짜를 Core에 전달한다.

## 처음 시작과 보유 덱

처음에는 SP0·GP0·보유 카드0장이다. 빛·물·불·숲·금속·대지·암흑 중 무료 기본 덱 하나를 고르면 해당 덱의 실제50장과 환영600SP를 한 번 받는다. 다시 선택해 다른 기본 덱이나 SP를 중복 지급받을 수 없다. 기존27개 연습 덱·2,646종 출전 카드·15,350개 원본 도감과 기존 전투/덱 저장은 삭제하거나 바꾸지 않는다.

수집 덱은 원래의50장·속성 지형·동일 카드 한도 검사에 더해 카드별 보유 수량을 검사한다. 다른 속성의 기본 덱50장 세트는 상점에서1200SP로 구할 수 있다. 이는 구성을 그대로 받는 확정 상품이다. 이미 보유한 카드도 중복 수집할 수 있지만 실제 덱의 카드 한도는 늘어나지 않는다.

## SP를 얻는 경로

- 무료 기본 덱 첫 선택:600SP 한 번.
- 실제 수집전 승리: 상대 티어1/2/3/4에 따라150/200/250/300SP. 같은 상대의 새 결투에서도 다시 받을 수 있다.
- 시나리오 첫 승리: 위 승리 보상에 장별300/400/500/600SP를 한 번 더 받는다. 이전 장을 깨야 다음 장이 열린다.
- 자연스럽게 끝난 패배:2턴 이상35SP, 턴 한도 무승부25SP. 자신의 포기는0SP다. 상대에게 `Concede`를 호출해 만든 승리는 보상을 지급하지 않는다.
- 목표: 첫 승리250SP, 누적3승400SP, 첫 상품 개봉150SP를 각각 한 번 받을 수 있다.
- 일일 목표: 한국 시간 해당 날짜에 실제 수집전에서 승리한 뒤150SP를 하루 한 번 받는다.
- 무료 부스터: 한국 시간 하루 A/B/C 중 하나를0SP로 받는다. 개봉하지 않고 남겨 두어도 그날의 무료 구매 한도는 사용된다.

단순히 결과 화면을 다시 열거나 창 크기를 바꾸고, 저장을 이어하거나 같은 완료 결과를 다시 전달하는 것으로 SP가 늘어나지 않는다. 완료한 결투의 재정산은 `alreadyClaimed=true`, 신규 지급0SP의 기존 영수증을 반환한다. 새 수집전은 별도의 거래 식별자를 갖는다.

## 부스터와 확률

일반/속성 부스터는400SP·5장이다. 일반4칸과 별도의 레어 확정 마지막1칸으로 구성한다. 상위 등급 부스터는1200SP·5장이며 일반4칸도 레어/스페셜/유니크/시크릿/레전드만 나오고, 마지막 칸은 스페셜/유니크/시크릿/레전드 중 하나다. 속성 상품에서는 해당 속성만 나온다.

실제 확률은 `FmQuestCatalog.GradeOdds(offerId, guaranteed)`와 각 상품의 `oddsText`가 계산한다. 기본 가중치에서 그 상품에 실제 출전 카드가 없는 등급을 제외하고 남은 가중치를 정규화한다. 따라서 속성·종류 상품별 확률은 다를 수 있다. 같은 등급/상품의 개별 카드는 동일 확률이며 복원 추출이므로 중복이 가능하다. 마지막 확정 칸을 일반 칸과 같은 확률로 소개하지 않는다. 팩에서는 원본 감상만 가능한 미지원 카드를 뽑지 않으며 실제 `CardCatalog.All`에 있는 출전 카드만 사용한다.

SP 지불 시점에 독립된 팩 RNG로 카드 결과를 한 번 결정해 구매 기록에 보관한다. UI는 미개봉 카드 앞면을 보여 주지 않는다. 개봉은 그 결과를 보유 카드에 한 번 반영하는 동작이며, 개봉 순서·재로딩·반복 클릭이 결과를 다시 굴리지 않는다. 전투의 RNG와 팩/결투 시작용 RNG는 독립적이다. 팩을 구매하거나 도감을 여는 행위가 진행 중 전투의 코인·드로우 순서를 바꾸지 않는다.

## 저장과 거래 경계

새 프로필은 별도 `fantasy-quest-profile-v1` 슬롯, schema1, `fm-quest-0.1.0` 봉투를 쓴다. `FmQuestProfile.version=1`과 기존 `CardCatalog.Version`을 확인한다. 기존 `fantasy-battle-classic-v3`·`fantasy-deck-classic-v3`의 바이트와 schema3은 유지한다. 수집전의 실제 전투 저장도 별도 슬롯을 사용한다.

프로필은 보유 수량·SP 장부·팩 구매/개봉 기록·수집전 거래·첫 완료 장·목표 수령 기록과 독립 RNG를 보관한다. 한 번 받은 기본 덱과 실제 개봉 결과로 보유 수량을 재구성하고, 원인 기록으로 SP 거래 장부를 검증한다. 패킷별 안정 ID·중복·음수·잔액·GP0·알 수 없는 카드/상품/목표·덱/소울 규칙·미개봉 결과 변조·팩 RNG 연속성·시나리오 순서를 검사한다. 잘못된 저장은 원본을 보존하고 거부한다.

`fm-quest-0.1.0`의 가격·확률·팩 후보 풀은 저장 계약의 일부다. 출시 뒤 카드 풀이나 가격/확률표를 바꿀 때에는 같은 버전의 값을 그대로 덮어쓰지 말고, 이전 거래를 원래 표로 검증하는 버전 분기와 명시적 마이그레이션을 추가해야 한다. 이미 개봉한 카드·잔액·미개봉 결과를 새 표로 다시 굴려 바꾸지 않는다.

수집전 시작은 보유 덱을 검사하고 독립 시작 seed와 거래 ID를 기록한다. 전투에는 기존 schema3과 호환되는 `quest-ticket` 이벤트 한 건을 추가해 기존 무료 연습 저장과 구분한다. 이어하기는 실제 원본100장 인스턴스 ID/정의, 상대·규칙·선택 리더와 거래 이벤트를 검증한다. 실제 덱 소진/턴 한도/자신의 포기와 일치하는 완료 결과만 정산한다. UI는 프로필/전투의 두 파일 쓰기 경계를 명시적으로 처리하며 실패 시 메모리 프로필을 스냅샷으로 복원한다. 고아 거래는 보상 없이 포기할 수 있다.

이는 로컬 싱글 진행이며 서버 서명이나 결제 보안/실시간 멀티 계정 경제가 아니다. 날짜는 로컬 시계이고 프로필은 로컬 저장이다. 나중에 결제를 추가할 때에는 서버 권위·구매 영수증 검증과 별도 경제 설계가 필요하다. 현재 GP를 지급하거나 실제 결제 창을 열지 않는다.

## 셔플

보존한 공식 온라인 안내 `tutorial2_1`의 ‘핸드6장을 덱에 넣고 섞은 뒤 차례대로 다시 받음, 해당 턴 카드 사용 전 한 번’은 현재 Core 전체 손패 셔플과 일치한다. 공식 가이드의 방 옵션4턴/6턴/무제한/없음과 종료 직전 기본값은 구분한다. 이번 경제 추가에서 기존 Core의 무제한 준비별1회 정책, 손패 인스턴스·RNG·LP/소울을 임의로 바꾸거나 확인되지 않은 셔플 비용을 붙이지 않는다. UI의 복귀/한 장씩 재분배 연출은 실제 이미 확정된 결과를 순서대로 보여 준다.

## 검증 범위

`Tools/Validation/Tests/FmQuestEconomyTests.cs`는 첫 덱/중복 지급, 실제 보유 덱, 팩 저장 왕복·확률과 등급 보장, 전투/팩 RNG 분리, 날짜별 무료 팩과 목표, 실제 AI 행동으로 끝낸 자연 승리·첫 클리어/중복 결과, 원래 연습 저장 비간섭, 적 포기 보상 거부, 고아 거래·저장 손상·DTO 방어 복사를 검사한다. 작성한 테스트를 실행 성공으로 소개하지 않는다. 실제 실행과 UI·Web·공개 URL 검증 결과는 이번 릴리스의 실행 담당 기록을 따른다.
