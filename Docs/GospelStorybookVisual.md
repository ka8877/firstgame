# 이야기책 개정의 빛과 탐험

`gospel-storybook-2026-11-02`의 실제 진입점은 기존 `GospelPilgrimageApp`과 X/Z 자유 필드다. Ori and the Will of the Wisps의 부드러운 광선·찬 그림자와 따뜻한 빛·살아 있는 식생·조용한 입자·탐험 동작을 시각 방향으로 참고한다. 상용 게임의 소스나 자산을 가져온 구현 또는 동일 품질이라고 소개하지 않는다. 옆보기로 되돌리거나 기존 여정의 실제 좌표를 바꾸지 않는다.

## 실제 필드 변경

첫 나사렛 출발 마당의 석재 포장을 가리던 큰 갈색 흙길을 포장 경계에서 끝낸다. 기존 석재 맵·우물·항아리·나무 원본을 보존한다. 마당 주변에 꽃과 올리브빛 풀의 국소적인 화단을 만들고, 기존 제작 나무의 크기와 외곽 배치를 보강한다. 성전의 넓은 석재 마당은 보존하며 이스라엘의 모든 장소를 울창한 판타지 숲으로 표현하지 않는다.

새 `GospelPilgrimageAtmosphere`가 각 장의 실제 지면 높이에 맞춰 충돌 없는 풀·작은 꽃·부드러운 광선·느린 꽃가루를 한 종류당 하나의 메시로 그린다. `PilgrimageMeadow.shader`는 뿌리를 고정하고 잎 끝만 움직이며 URP 주광원과 그림자를 받는다. `PilgrimageAtmosphere.shader`는 투명 광선·먼지·강물의 가느다란 반사를 원본 텍스처 없이 직접 그린다. 두 셰이더는 Resources에 보존하여 Web 빌드에서도 참조한다. 분위기용 빛은 서사의 기적이나 성경에 기록된 자연 현상을 주장하는 장치가 아니다.

Native01의 실제 첫 필드 검토에서 카메라에 보이는 이동 경계 밖의 넓은 빈 땅과 미세한 풀의 크기가 드러났다. 이를 보완해 서쪽·남쪽 경계의 기존 원본 수풀을 높이1.1–1.85m의 큰 무리로 배치하고, 충돌 없는 큰 암석과 부드러운 타원형 지면 색 무리를 더했다. 광선 폭과 투명도도 조정했다. 포장·기존 충돌·목표·실제 이동 경로는 바꾸지 않았다. 첫 실패 원본과 이후 수정 실행은 구분한다.

나사렛과 성전은 금빛 석재·푸른 올리브 그림자로, 요단강은 옅은 청록 반사·갈대 무리·움직이는 은빛 수면으로 구별한다. 꽃과 풀은 실제 목표·이동 경로와 포장 공간을 비워 두며 새 충돌체를 만들지 않는다. 기존 나무·벽·우물의 실제 충돌은 유지한다. 카메라는 43도 경사, 기본 직교 크기6.4, 줌 범위5–12로 인물을 더 가까이 보여주며 앞뒤·대각선 이동과 마우스 휠 줌을 유지한다.

## 짧은 탐험 대시

`GospelPilgrimageMotor.RequestDash()`는0.19초 동안 현재 바라보는 방향으로 짧게 이동한다. 속도11.2m/s, 재사용 간격0.88초이며 기존 `CharacterController.Move`와 실제 충돌·필드 경계·중력·점프를 사용한다. 벽 통과·무적·전투 판정을 추가하지 않는다. 메뉴가 열리거나 모터가 비활성화되면 즉시 취소한다. Native02에서 드러난 저프레임 외부 UI 요청의 유실은 요청을 보관하고 실제 첫 Motor.Update에서 시작하는 방식으로 수정한다. 대시 속도는 실제0.19초 물리 구간에만 적용해0.25초 이상의 한 프레임에서도 이동 거리가 과대해지지 않게 한다. 실제 시작 횟수는 DashSequence로 관측한다. PC Ctrl, 게임패드 동쪽 버튼과 터치 대시 버튼으로 사용할 수 있다.

기존12프레임/4방향 인물 PNG·측정 UV·발 기준·.meta·GUID는 바꾸지 않는다. 대시 동안만 같은 원본 프레임의 작은 잔상4개를 최대0.17초 표시한다. 인물의 관절이나 몸통을 별도로 비틀지 않으며 이동은 모터, 그림은 Actor가 맡는다. 등잔의22cm 최대 길이·실제 장착/광원·원본 재질과 골격도 보존한다.

## 검증 경계

`GospelRepriseVisualSmokeTests.RealExplorationDashStopsAtCollisionAndCannotBypassCooldownOrModal`은 실제 지면과 벽에서 대시의 이동·막힘·재사용 제한·메뉴 중지·열린 공간의 짧은 이동을 검증한다. Native01의 고정0.22초 대기 후 접지 검사 실패는 숨기지 않고 보존한다. 다음 fixture는 편집기 포커스/남은 입력을 격리하고 원설정을 복구하며, 제한2초 내 실제 접지를 기다려 같은 접지·벽·재사용 검사를 수행한다. 접지를 만들거나 모터를 이동시켜 통과시키지 않는다. Native02의 접지는 통과했지만 외부 요청 후 첫 대시 이동0.00065m 실패는 실제 저프레임 입력 유실로 확인돼 생산 모터를 수정했다. 다음 검증은 첫 실제 시작과 벽·재사용을 유지하며, 열린 공간에서는 Unity captureDeltaTime=0.25의 긴 프레임으로 요청 보존과1.1–3.2m 거리 제한을 검증하고 원래 타이밍 설정을 복구한다. 소스 작성과 실행 통과는 다르며, 실제 실행 결과와 현재 PC/터치 화면은 `Artifacts/Validation/Reprise`의 새 근거를 따른다. 이전 Quest 스크린샷을 새 화면의 검증으로 재사용하지 않는다.


## 우물 목재 재질의 비정상 픽셀 수정

첫 Web 터치 검토에서 샘터 쪽으로 이동했을 때 큰 흰 번짐이 드러났다. 최초 실패 원본과 Web01 바이트는 별도로 보존했다. 실제 Native 제어 대조는 초기 마당·샘터/마리아·요단의 동일한 생산 World/Actor/Camera를 명시적인 진단 좌표에 두고 Bloom·DoF·Atmosphere·후처리를 각각 비교했다. 이는 일반 게임 이동 성공의 근거가 아니다.

후처리를 모두 끈 ARGBHalf→RGBAFloat 읽기에서 샘터만230,400픽셀 중129개의 NaN이 검출됐고, 유한 RGB 최대는 약1.045였다. 초기 마당·요단은0개였다. 다음 독립 대조에서 우물 렌더러 제외만129→0으로 바뀌었으며, 풀·공기 효과·인물 제외는129개가 유지됐다. 우물의 각 재질을 하나씩만 임시 Unlit로 바꾼 대조에서도 `Well_Cedar`만0개가 됐다. 다른 다섯 재질은129개가 유지됐다. 정상 색의 밝기가 과했던 문제가 아니라 우물 목재의 Lit 경로에서 발생한 비정상 픽셀이 Web 후처리에서 확산된 문제다.

정상맵 키워드만 끄는 최소 대조를 먼저 시행했지만 Native04에서129개의 NaN이 그대로 검출됐다. 원본 albedo를 연결한 URP Unlit 대조도 Native05에서129개가 유지됐다. 최초 plain Unlit 대조에는 텍스처가 연결되지 않았으므로, 이 결과를 텍스처가 연결된 경로의 성공으로 소개하지 않는다. 원본 FBX를 읽기 전용으로 분석한 결과도 정점·normal·11개 UV 층은 모두 유한했다. 원본 파일의 UV에 NaN이 있다고 주장하지 않는다. 관측으로 확정한 범위는 Cedar의 런타임 텍스처 샘플링 경로이며 imported UV/implicit LOD/그래픽 드라이버 중 어느 내부 동작인지까지 입증하지 않았다.

현재 수정은 이 필드에서 생성한 **런타임 Cedar 복제 재질만 `PilgrimageCedar.shader`로 그리는 것**이다. 같은 원본 목재 albedo와 색을 사용하되 imported UV·normal·tangent를 읽지 않고, 유한한 실제 월드 좌표를 반복 좌표로 만든 뒤 명시적인 LOD0으로 샘플링한다. 목재 기하·충돌·깊이·불투명 그림자 패스는 유지하며 다른 석재·물·철제 재질과 환경 조명을 변경하지 않는다. 원본 `.mat`의 Lit 셰이더·정상맵·PNG·FBX·GUID·가져오기 설정은 수정하지 않는다. 같은 원시 HDR 회귀 검사에서 실제 결과를 확인하며 실패한 이전 두 수정도 이력으로 남긴다.

카메라에는 URP `stopNaN`을 보조 방어로 켠다. Bloom·DoF와 화면의 빛 목표는 유지한다. 새 `GospelRepriseFiniteRenderingTests`는 이 방어와 모든 후처리를 **끄고** 원시 HDR의 NaN/Inf가0인지 검사하므로 방어 처리로 원인 픽셀을 숨겨 통과시킬 수 없다. 보존 원본 재질의 Lit 셰이더·정상맵과 런타임 복제의 원래 albedo·색·텍스처 설정 및 새 유한 좌표 경로를 대조하고, 샘터와 요단의 PC/좁은 화면 원본을 생성한다. `Core.Runtime`의 직접 참조1줄은 이 영구 렌더 회귀 검사의 정식 의존성이다.

임시 진단 Entry의 실제 소스와 메타·해시는 `Artifacts/Validation/Reprise/WhiteProbe/Source01`·`Source02`에 보존했다. 원래 asmdef 바이트를 실제로 복원/검증한 뒤 정식 참조를 추가했으며, 임시 Entry만 제거한 기록은 `temporary-entry-restoration.json`이다. 정확한 최종 실행 통과 여부와 공개 수정은 새 Reprise 실행 기록을 따른다.
