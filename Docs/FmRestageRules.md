# 판타지마스터즈 Restage 규칙과 카드 수치

개정 `fm-restage-2026-11-02`. 기존 2,646종 출전 카드, 15,350개 보존 원본, 27개 자유 연습 덱, 카드 ID·원본 PNG·종횡비와 schema3를 유지한다. 원작 클라이언트 전체 복구나 종료 직전의 모든 카드·예외 규칙 지원을 주장하지 않는다.

## 카드 위 실제 수치

기존 Core의 `CardCatalog.UnitAttack/UnitDefense/UnitHealth`는 이미 장착 아이템, 현재 전투 코인, 기술, 누적 피해를 포함했다. 그러나 재생 화면은 사건 **이전** 스냅샷으로 카드를 만들고 애니메이션을 끝낸 뒤 다음 스냅샷으로 넘어갔다. 코인에는 행동 유닛의 수치만 임시로 덮어쓰는 예외가 있었고 아이템을 받는 유닛·기술 대상·피격 유닛에는 없었다. 따라서 코인 창, 행동자 메타데이터, 실제 카드 얼굴이 같은 시점의 수치를 표시하지 못했다.

`FmLiveCardValues`는 카드 인스턴스 ID에 연결되는 표시 전용 컴포넌트다. 필드 카드, 중앙 교전 카드와 코인 수치 창 모두 정확한 현재 사건의 `BattlePlaybackFrame.players`에서 AP·DP·남은 HP를 받는다. 코인이 멈출 때, 장착이 닿을 때, 공격이 명중할 때 해당 프레임의 값으로 갱신한다. 자리를 옮기거나 소각되는 카드를 미리 없애지 않도록 카드 위치·존재·상대 정보 공개는 기존 사건 이전 스냅샷을 유지한다. 표시 코드는 코인 RNG나 UnitState를 변경하지 않는다. 생존 유닛의 전투 수치 회복은 Core의 실제 다음 준비 단계 스냅샷을 따른다.

인쇄 수치 자리에 있는 기존 불투명 숫자판만 갱신한다. 원본 AP/DP/HP 아이콘, 원화·이름·등급·기술 문장, 카드 비율을 보존한다. 실제 값이 인쇄 기본치보다 높거나 낮으면 색을 유지한다. 앨범/손패는 기본 수치, 필드/교전은 실제 인스턴스 수치이며 원본 상세는 전체 인쇄를 그대로 보여 준다.

공개 읽기 API `BattlePlaybackStatsCommitted`, `BattlePlaybackResolvedStatsSnapshot`은 표시 사건이 실제 수치로 넘어갔는지 검사하기 위한 것이다. 후자는 깊은 복사이며 실제 전투를 소유하지 않는다. `BattlePlaybackDisplaySnapshot`은 이동·파괴 연출용 사건 이전 배치 상태로 남는다.

## 미사용 지형의 소각

[2005년 공식 오프라인 매뉴얼 보존본](https://web.archive.org/web/20051101013311id_/http://www.fantasymasters.co.kr:80/Guide/Manual/tutorial6.asp)은 “준비완료 전에 어느 시점이라도 카드를 소각 … (소울을 사용한 지형은 소각불가)”라고 명시한다. 사용한 지형은 오른쪽으로 꺾어서 표시하라는 문장도 있다. 보존 응답의 URL·조회일·해시·확인 문장은 [이전 직접 조회 기록](../Tools/Research/FmFidelity/hand-discard-official-evidence.json)에 있다. 이번에 직접 재조회한 [2016-09-11 공식 FAQ734](../Tools/Research/Restage/faq734-2016.json)와 [2015-09-01 플레이어 가이드](../Tools/Research/Restage/guide-2015.json)에서 이 제한을 뒤집는 근거나 지형별 지불 순서를 확인하지 못했다. 2005 규정을 종료 직전의 직접 확인 문장으로 소개하지 않는다.

기존 Reprise는 지형별 소울 사용 기록이 없어 지형 소각 전체를 잠갔다. 이번에는 `CardInstance`에 선택적 schema3 필드 `hasSoulProductionRecord`, `terrainSoulUsed`, `remainingColoredProduction`, `remainingGenericProduction`을 추가한다. 실제 전개·소울 회복 때 자원 상한 내에 들어온 생산량만 그 지형에 기록한다. 색 비용과 총소울 비용, 유지비와 솔버스트의 실제 소울 지출을 기록하고, 한 부분이라도 쓴 지형은 다음 소울 회복까지 임의 소각할 수 없다.

미사용 지형을 소각하면 해당 지형의 아직 사용하지 않은 색·총소울 생산량도 제거한다. LP를 돌려주거나 이미 낸 카드의 비용을 취소하지 않는다. 생산 상한에 막혀 실제로 추가되지 않은 자원을 다른 지형/효과의 자원에서 빼앗지 않는다. 유닛 강화 생산이나 별도 효과로 늘어난 자원은 지형 생산과 구분한다.

동일한 소울 중 어느 지형이 지불하는지를 정의한 공식 문장은 확보하지 못했다. 이 구현은 비지형/사용 출처 미확인 소울을 먼저 지출하고, 남은 색 비용을 같은 속성 지형의 필드 순서로 지출하며, 총소울은 그때 사용한 지형을 우선한다. 이는 **재구성의 결정적 배분 정책**이다. 원작의 숨은 자동 선택 순서를 복구했다고 주장하지 않는다.

이전 schema3에서 새 필드가 없으면 사용 여부는 미확인이다. 로드 중 원본을 고치거나 지출하지 않았다고 추측하지 않는다. 기존 지형은 다음 실제 소울 회복에서 새 기록을 받기 전까지 소각이 제한되고, 새로 전개한 지형에는 즉시 실제 생산 기록을 만든다. 복사·중간 재생 프레임·저장 재개가 이 기록을 보존한다.

## 확인 범위와 남은 차이

2016 보존 FAQ734는 코인 기본 확률 50%, 카드별 1–5개 코인, 코인으로 AP/DP/HP가 함께 변하는 예와 일반 공격에 DP 자체가 줄지 않는 점을 설명한다. 해당 내용은 기존 Core와 일치하며 이번에는 표시를 바로 연결한다. 확률/코인 수를 바꾸는 실제 아이템과 현재 지원 기술의 원문 데이터는 보존한다. DP를 바꾸는 기술과 일반 타격의 피해 계산을 혼동하지 않는다.

고정 `*`, 하한 `▲`, 상한 `▼` 능력치, 인챈트의 독립 단계·지속 턴, 모든 지형/장착 예외와 모든 보존 카드의 기술 지원은 이 변경으로 완성되지 않는다. 미지원 원본을 기술이 없는 출전 카드로 바꾸지 않는다. 신규 규칙 근거와 재구성 정책, 이전 승인 증거와 이번 실제 실행 결과를 구분한다.

실제 2015 가이드의 칠성보검은 `=4 / 0 / +3`이며, 전체 DB 보존 행 `11080341289`의 `ATKStatType=33(EQUAL)`도 대입 연산을 나타낸다. 2016 FAQ의 파랑새의 깃털도 DP를 2로 고정하는 예다. 현재 출전 아이템 **284종**의 각 `ATK/DEF/HPStatType`은 `1(NONE) / 31(PLUS) / 32(MINUS)`만 허용되고 제작기 역시 이를 검사한다. 따라서 출전 범위의 합산 수치는 그 제한 안에서 맞지만 모든 원작 장비가 더하기라는 뜻은 아니다. 칠성보검은 원본 열람으로 보존하고 `playable=false`이며 대입·고정 장비를 합산 장비로 바꾸어 출전시키지 않았다. 2015 인쇄의 확률 문구와 현재 DB 행의 `ProbOption`도 시기 차이가 있을 수 있어, 서로 다른 시점의 예를 섞어 현재 카드에 새 효과를 넣지 않는다.

## 검증 계약

`RestageTerrainTests`는 생산 회수·사용 지형 거부·상한/비지형 자원 보존·유지비·이전 JSON 필드 누락·깊은 복사·동일 RNG 재개를 검사한다. `RestageValueFramesTests`는 행동자가 아이템인 사건의 실제 장착 대상 HP, 장착 해제와 중간 프레임 독립성, 명중 시 HP0과 이어지는 실제 파괴 순서·유지되는 DP를 검사한다. Native 검증은 코인 창뿐 아니라 실제 카드 숫자 TMP의 장착·앞면 코인·피해 갱신을 검사하고 PC/모바일 원본을 확인해야 한다. 실행·빌드·브라우저와 결과 기록은 `remaster_release`가 소유하며 현재 결과는 [Restage 검증 폴더](../Artifacts/Validation/Restage)를 따른다. 이 문서의 구현 설명 자체는 실행 통과 증거가 아니다.
