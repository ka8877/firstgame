# 예수님의 생애를 따라 채우는 성경

`gospel-chronicle-2026-10-29`의 새 여정은 단순히 같은 숲에서 탄생을 회상하는 만남을 반복하는 대신, 기록 순서의 장면과 실제 목표를 잇는다.

1. **탄생과 아기 때의 서막**: 호적 여행·탄생·목자들·이름·성전 봉헌·시므온·안나·나사렛의 성장을11개 그림 장면으로 읽는다. 아직 움직일 수 없는 영아를 소년 인물로 걷게 하지 않는다. 읽기를 마친 말씀만 성경에 기록된다.
2. **열두 살 · 성전의 소년**: 나사렛에서 출발 준비→가족과 유월절 길→예루살렘 뜰→듣고 묻는 자리→선생들 가운데→부모와의 만남→나사렛 귀향의7개 목표다. 출발과 길 안내는 게임용 극화로 표시하고, 예수님의 기록되지 않은 질문과 대답을 실제 발언으로 창작하지 않는다.
3. **공생애의 시작 무렵 · 요단강**: 성인 인물과 별도의 강가 풍경에서 안내자→세례 요한의 사역→세례 요청→물에서 올라오신 기록→가르치심을 시작한 나이의5개 목표를 잇는다. ‘삼십세쯤’을 정확한 생일로 바꾸지 않는다.

현재 구현 범위는23개 목표·19개 성경 본문 묶음이다. 원래15개 본문의 ID와 단어는 보존하며 공식 개역한글의 누가복음3장·마태복음3장 네 묶음을 추가한다. 이후의 광야·사역·십자가·부활·승천은 이 구간에서 플레이 가능한 것처럼 표시하지 않는다. 정확한 인용과 출처·게시물 원본은 [본문 조사](GospelChronicleSources.md)에 있다.

## 성경과 발견

M 또는 HUD의 **성경**을 누르면 가죽 제본·종이 면·중앙 책등을 가진 펼친 책을 연다. 처음에는 미발견 면의 제목·출처·본문·장면 그림이 모두 감춰져 있다. 이전/다음 면을 넘기는 행위는 말씀을 획득하지 않는다. 해당 이야기의 마지막 대화를 마친 경우에만 본문과 그림이 그 면에 나타난다. 본문 영역은 위아래로 읽을 수 있으며 **여정으로**를 누르면 직전에 열었던 대화 또는 이동으로 돌아간다.

J 또는 오른쪽 기록 아이콘은 별도의 **여정 기록**이다. 완료한 만남과 현재 목표만 보이고 미래 목표를 미리 펼치지 않는다. 성경책의 본문과 RPG의 목표 목록을 분리한다.

각 실제 이동 목표는 현재 위치가 목적지 반경 안에 들어왔는지를 Core에서 검사한다. E/대화 버튼으로 NPC와 만나고 현재 대화를 이어간다. 책·메뉴·대화 중에는 이동 입력이 풀린다. 다음 장으로 넘어갈 때는 장 제목과 현재 나이를 먼저 알리고 새로운 출발점·인물·풍경을 적용한다. 현재 아이템·등잔·달리기·점프·줌·H풍경 보기와 복귀는 유지한다.

## 인물과 원본

소년은 기존 그림의 팔에 중복된 소매를 줄이고 연속된 관절 변형을 적용한다. 성인은 새 전신 원화에 측정한 영역과 가중치를 적용한다. 새 요단강 풍경과 세례 요한은 별개의 오리지널 원화다. 생성된 PNG 원본의 바이트·알파를 보존하며 `Tools/Art/GospelChronicle/manifest.json`에 경로·해시·제작 한계를 기록한다. 상용 게임 소스나 자산을 가져온 결과로 소개하지 않는다. 배경은 학습용 게임의 미술적 표현이며 고대 공간의 실측 지도는 아니다.

## 저장 호환

기존 schema1·콘텐츠 버전·슬롯 ID는 유지한다. 새 진행은 선택적인 `chronicle` 상태로 보관하고, 이전7개/15개 말씀 저장은 원래 경로로 계속 열 수 있다. 완료한 이전 여정에서는 **여정 기록 → 요단강의 여정으로**를 선택할 수 있다. 이때 새 슬롯으로 분기해 이전 완료 저장을 보존하고 이미 발견한 말씀만 계승한다. 중간 대화·현재 목표·발견한 말씀은 저장 후 다시 이어진다. 아직 읽지 않은 말씀을 이전 완료 처리만으로 전부 채우지 않는다.

실제 Unity 검사에서 `JsonUtility.FromJson`과 `FromJsonOverwrite`는 누락된 인라인 `chronicle`을 version0 객체로 만들었고, `ToJson`도 null 필드를 같은 객체로 기록했다. `GospelSaveCodec`은 기존 잠금 패키지 Newtonsoft3.2.2로 원문 JSON의 최상위 필드 유무를 확인한다. 실제 누락/null만 이전 저장으로 읽고, 명시한 version0·잘못된 형식·중복 키·문서 뒤 추가 내용은 거부한다. 이전 진행을 저장할 때만 합성 필드를 생략한다. Core의 진행 검증은 완화하지 않으며, 기존 원본 슬롯을 새 필드가 있는 시험 파일로 바꿔 통과시키지 않는다. 새 전체 여정과 기존7항목 저장의 실제 이어하기·왕복 저장은 별도 Unity 검사로 확인한다.

검증은 [이번 실제 결과](ChronicleValidation.md)를 따른다. 설계상의 목표 수나 Core 검사를 실제 브라우저에서 전 장을 읽은 결과로 대신하지 않는다.
