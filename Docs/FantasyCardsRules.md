# 별빛의 서약 — Rules v0.1

이 문서는 **판타지마스터즈 1의 확인 자료**와 **이 프로젝트의 설계값**을 구분한다. 판마 1의 복제나 수치 재현을 주장하지 않는다. 카드 이름, 그림, UI, 스토리는 오리지널이다.

## 확인한 원작 자료

2026-10-20 조사. 다음 URL을 실제 HTTP로 열어 본문을 읽었다.

1. [Fantasy Masters — Gameplay / Coins / Constructing Deck](https://en.wikipedia.org/wiki/Fantasy_Masters), 2002년작의 2차 정리. 2016년 후속작은 소개 문단에서 별도로 구분된다. 문서 자체에 출처 보강 경고가 있으므로 아래 내용은 2차 자료에서 확인한 범위다.
   - Land, Unit, Item, Spell의 4종 분류.
   - 후열 지형이 soul 자원을 만들고, 전열 유닛·마법이 전투에 참여하는 준비/전투 구조.
   - 유닛 전투의 코인으로 AP/DP/HP가 변하는 구조.
   - 이 정리는 덱 50장, 지형 한도 10장, 최대 5코인, 7속성을 설명한다. 본 프로젝트 수치로 가져오지 않았다.
   - 원작 마법은 뒤집어 놓은 뒤 전투 때 공개하고 낮은 레벨부터, 동률이면 공격측부터 처리한다고 기술한다. 본 프로젝트의 즉시 시전과는 다르다.
2. [2007-02-17 원작 공식 홈페이지 보존본](https://web.archive.org/web/20070217213433/http://www.fantasymasters.co.kr/). 2016년 판마2 이전의 공식 페이지임을 확인했다. 카드 마켓/덱 스토어/교환 등 당시 원작 메뉴가 남아 있다. 세부 가이드는 Flash와 과거 ASP 경로에 의존하여 이번 조사에서 규칙 본문을 추가 검증하지 못했다.

원작 생명/덱 고갈 판정, 공격·방어 편성 상세, 효과 우선순위의 지역·버전 차이는 1차 가이드로 교차 검증하지 못했다. 이를 확정된 원작 규칙으로 취급하지 않는다. 판마2의 리뷰나 수치를 구현 근거로 사용하지 않았다.

## 이 프로젝트의 v0.1 설계 가정

| 항목 | 현재 기본값 / 동작 |
|---|---|
| 속성 | 여명, 조류 2종 |
| 카드 정의 | 16종 = 지형 4 + 유닛 6 + 마법 3 + 장비 3 |
| 덱 | 각각 24장. 기본 덱은 지형 8 / 유닛 10 / 마법 3 / 장비 3 |
| 생명 / 승리 | 생명 18. 0 이하인 쪽 패배. 동시 0은 무승부 |
| 손패 | 시작 5장, 한도 9장. 한도 초과 드로우는 버림 |
| 튜토리얼 시작 | 섞인 덱에서 각 속성 지형 1장씩 먼저 확보한 뒤 나머지 손패를 뽑음 |
| 턴 드로우 | 첫 선공 턴은 추가 드로우 없음. 이후 각 턴 시작 1장 |
| 탈진 | 덱이 비면 드로우 대신 1, 2, 3… 증가하는 생명 피해 |
| 지형 | 턴당 1장, 전장 최대 6장. 설치 즉시 해당 자원 1, 내 턴 시작마다 1 |
| 자원 | 지불 후 남은 자원 유지. 속성별 최대 12. 다른 속성으로 대체 지불 불가 |
| 전장 | 각 플레이어 3칸. 배치 칸 선택. 소환 유닛은 계속 남음 |
| 소환 대기 | 다음 자신의 턴 전까지 공격·가로막기 불가. 직접 공격 대상으로는 선택 가능 |
| 전투 | 준비 → 공격 선언 → 상대 방어 대응 → 판정 → 다음 공격 또는 턴 종료 |
| 공격 대상 | 적 서약자 또는 적 유닛을 선택. 상대 준비 유닛은 선언 대상을 대신 가로막을 수 있음 |
| 가로막기 | 준비된 유닛 1개를 선택하거나 가로막지 않음. 선언된 유닛은 가로막지 않아도 전투 대상 |
| 행동 소모 | 공격 선언 또는 가로막기 참여 시 소모. 내 다음 턴 시작에 회복 |
| 반격 | 유닛 대 유닛이면 기본적으로 동시 피해. 직접 공격받는 소모된 유닛도 반격함 |
| 코인 | 기본 1개. 앞면마다 카드에 쓰인 공격 보너스. 장비로 추가 가능 |
| 마법 | 준비 단계에 즉시 해결. 회복/피해/지속 공격 증가의 3종 |
| 장비 | 아군 유닛당 2개. 유닛이 전장을 떠나면 함께 버림 |
| 시간 제한 | 전체 60턴 뒤 생명 비교. 같으면 무승부 |
| 덱 편집 | UI에서 카드당 4장까지, 정확히 24장/지형 4장 이상/유닛 6장 이상일 때 저장 |

전투 코어의 `RuleSet`에서 덱/손패/전장/지형/자원/생명/턴 한도, 시작 보장, 반격 여부, 기본 코인 수, `coinOrder`(공격측 먼저/방어측 먼저), `damageOrder`(동시 피해/공격 우선 피해)를 바꿀 수 있다. 공격 우선 피해에서는 치명상을 받은 수비 유닛의 반격 피해를 취소한다. 양측 코인 결과 기록은 피해 전에 완료한다. 현재 튜토리얼 UI의 덱 편집 조건은 24장에 맞춰져 있으므로 다른 RuleSet을 제품화할 때 UI도 변경해야 한다.

기본 해결 순서는 **공격 선언 → 방어 선택 → 공격 코인 → 방어 코인 → 피해 동시 적용 → 칸 순서대로 사망 제거 → 승리 확인**이다. 준비 단계의 마법/장비는 비용 지불 → 효과 적용 → 사망 제거 → 승리 확인. 판정은 모두 코어가 수행하며 UI는 `BattleEvent`를 재생하기만 한다.

## 결정론과 저장

- Xorshift32 상태는 `BattleState.randomState`에 저장. 셔플과 코인만 난수를 사용한다. 0 seed는 1로 정규화한다. 정수 범위 선택은 rejection sampling을 쓴다.
- 같은 상태·RuleSet·콘텐츠 버전·행동이면 같은 사건 순서와 난수 상태로 진행한다.
- AI는 비용/종류/인스턴스 ID 정렬, 공격력/칸 정렬, 방어 체력/칸 정렬로 결정을 내린다. 생성형 API와 별도 난수 호출이 없다.
- `BattleState.Copy()`는 RuleSet/플레이어/카드/유닛/장비/로그를 복제한다. 실시간 상태는 ScriptableObject를 변경하지 않는다.
- 저장에는 덱/손패/지형/버림/유닛/장비/피해/자원/단계/선언/코인 상태/사건 기록을 포함한다. 방어 대응 도중도 복원 가능하다.
- 스키마 1 및 콘텐츠 `starlight-0.1.0`이 다르면 불러오기를 거부한다. 카드 총수와 중복 ID, 슬롯, 자원, 현재 공격 대상 등을 검증한다.
- 콘텐츠 값을 변경할 때는 `CardCatalog.Version`을 올려 이전 저장을 실수로 다른 규칙에 불러오지 않게 한다. 마이그레이션은 별도 후속 작업이다.
