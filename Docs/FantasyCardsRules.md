# 판타지마스터즈 클래식 체험판 규칙

현재 콘텐츠는 **`fm-classic-0.1.0` / 전투 schema 3**, 작업 기준일은 2026-10-26 UTC다. 공개 원작 DB의 카드 96종과 공식 가이드 보존본을 바탕으로 구현했다. 원작의 모든 시기·온라인 패치·카드 예외를 재현한 것으로 설명하지 않는다. 자료의 성격과 재사용 범위는 [클래식 제작 계약](FantasyMastersClassic.md), [규칙 조사](Research/FantasyMastersRulesSources.md), [카드 DB 조사](Research/FantasyMastersDatabaseSources.md)를 따른다.

이전 `starlight-0.2.0`의 오리지널 카드 40종·2속성·24장 덱·리더 생명 18·능동 리더 기술·수동 공격/가로막기는 **이전판의 규칙**이다. 기존 소스와 문서는 Git 이력에, 이전 빌드와 검증 결과는 지정 이력 폴더에 보존한다. 아래 표는 현재 클래식 구현이다.

## 자료와 구현 선택

전투 순서는 [2005년 공식 오프라인 가이드](https://web.archive.org/web/20051101013311id_/http://www.fantasymasters.co.kr:80/Guide/Manual/tutorial6.asp)를 기준으로 한다. 6장 전체 손패 셔플과 선택 옵션은 [공식 온라인 UI 가이드](https://web.archive.org/web/20050807002655id_/http://www.fantasymasters.co.kr:80/Guide/Manual/tutorial2_1.asp), 덱 구성은 [공식 덱 가이드](https://web.archive.org/web/20050715025816id_/http://www.fantasymasters.co.kr:80/Guide/Manual/tutorial4.asp)를 함께 읽었다. 색 소울과 총소울의 지불·회복은 원작 FAQ 재수록과 서비스 당시 플레이어 가이드로 보완했다.

다음 사항은 근거 수준 또는 체험판 선택을 구분한다.

- **코인 공통열의 앞 n개:** Cn의 앞면 수가 0…n이고 AP/DP/HP가 코인열을 공유한다는 자료를 종합해, 한 번 굴린 공통열의 앞 n개에서 앞면 수를 센다. 정확히 “앞 n개”라고 명시한 공식 문장은 아직 확인하지 못했다.
- **아이템 2장 상한:** 유닛당 최대 2장은 이번 구현의 상한이다. 공식 자료로 원작의 정확한 장착 개수 제한을 확정하지 못했다. 장비·마법·야수 능력의 장착 조건은 공식 카드 가이드에 근거한다.
- **매 준비의 전체 손패 셔플:** 공식 온라인 가이드의 4턴/6턴/무제한/없음 중 무제한 옵션을 이번 체험판에 선택했다. 여기서 무제한은 매 준비마다 허용한다는 뜻이며, 같은 준비에서 여러 번 섞는 뜻이 아니다. 카드 사용 전에 한 번만 가능하다. 서비스 모든 시기의 기본 설정이었다고 주장하지 않는다.
- **생존 유닛 능력치 회복, 최대 5코인, 양측 동시 소진 시 공격측 승리:** 확인한 2차 자료를 적용했다. 공식 오프라인 본문에서 모두 명문화된 것으로 취급하지 않는다.
- **60턴 제한, 소울 수치 상한 50:** 체험판의 종료·상태 관리 값이다. 제한 턴까지 승부가 나지 않으면 남은 덱 수를 비교하고 동률은 무승부다. Core의 실험용 Life 모드와 시작 라이프 50도 원작의 확정 수치로 소개하지 않으며, 현재 UI는 Deck 모드를 사용한다.

|---|---|

| 덱 | 50장, 동일 카드 최대 4장, 최소 지형 1장. 편집기는 유료 카드 속성의 지형도 요구 |
| 아바타 | 리리아·카엘·세린·노아 중 선택. 전투 능력이나 리더 기술 없음 |
| 승리 | 상대 덱이 0장이 되면 승리. 양측 동시 소진은 공격측 승리. 보충할 카드가 없는 경우도 패배 |
| 손패 | 시작 6장. 매 라운드 양측 손패의 부족분을 6장까지 보충 |
| 시작 카드 | 덱 전체를 실제 셔플해 뽑음. 지형이나 특정 속성을 강제로 보장하지 않음 |
| 손패 셔플 | 자신의 준비 단계에서 카드 사용 전 1회, 손패 전체를 덱에 넣고 섞어 같은 수를 다시 뽑음. 같은 인스턴스가 다시 나올 수 있음 |
| LP | 매 라운드 양측 +1, 사용하지 않은 LP는 남음 |
| 지형 | 전장 최대 10장. LP가 충분하면 한 준비에 여러 장 전개 가능. 선택된 지형은 모두 LP 1 |
| 소울 생산 | 선택된 지형은 해당 색 소울 1과 총소울 1을 생산. 설치 즉시 반영하고 소울 코스트 단계에 생산량으로 재산정 |
| 지불 | 색 소울 요구량과 카드 전체 소울 비용을 각각 색 한도·총소울에서 차감. 다른 색으로 대체 불가 |
| 전열 | 양측 각 5칸. 유닛과 예고 마법이 칸을 공유 |
| 준비 | 공격측 준비 → 방어측 준비. 양측 모두 지형·유닛·마법·아이템을 사용할 수 있음 |
| 소환 유닛 | 배치한 라운드부터 전투에 참여. 이전판의 소환 대기 없음 |
| 마법 | 전열 빈 칸에 예고. 공격 전용·방어 전용·공용 구분. 양측 준비 완료 후 공개·해결 |
| 전투 | 전열 순서로 자동 판정. 공격 유닛은 한 번 공격, 살아 있는 첫 방어 유닛은 계속 방어 |
| 반격 | 공격측 선타 후 방어 유닛이 살아 있으면 반격. 기본 물리 피해는 max(0, AP − DP) |
| 직접 공격 | 방어 유닛이 없으면 공격 유닛의 레벨만큼 상대 덱을 소각. AP로 계산하지 않음 |
| 코인 | 카드별 AP/DP/HP 코인식, 최대 5개, 유닛당 해당 전투에서 한 번만 판정 |
| 유지비 | 전투 후 양측 소울을 생산량으로 회복하고 살아 있는 **유닛의 무속성 비용** 합을 총소울에서 지불. 부족분은 덱 소각 |
| 아이템·마법 유지비 | 사용 시 소환 비용은 지불하지만 매 라운드 유닛 유지비에 더하지 않음 |
| 다음 라운드 | 생존 유닛의 일시 AP/DP/HP 변동·누적 피해·코인을 초기화. 장착 아이템은 유지. 공수 교대, 양측 LP 증가와 손패 보충 |

색 비용과 무속성 부분을 총소울과 혼동하지 않아야 한다. 예를 들어 **듀라한**은 레벨 4, 암흑 2 + 무속성 2다. 소환할 때 암흑 한도 2와 총소울 4를 지불하고 이후 유지비는 총소울 2다. 암흑 한도만 남고 총소울이 부족하면 낼 수 없다. 미사용 소울은 계속 누적되지 않지만 LP는 남는다.

## 전투 처리 순서

1. 공격측이 카드를 배치하고 준비 완료한다. 방어측이 자신의 카드를 배치하고 준비 완료한다.
2. 예고 마법을 낮은 레벨부터 해결한다. 같은 레벨은 공격측 먼저, 같은 측은 전열 순서다. 상대 예고의 이름·레벨은 화면과 준비 로그에서 숨기고 공개 이벤트에서 표시한다.
3. 각 마법의 범위·조건·변화량을 스냅샷으로 정한 뒤 적용하고 HP가 0 이하인 유닛을 제거한다. 마법도 해결 중에는 자기 전열 칸을 차지하며, 해결 후 버림 영역으로 이동한다.
4. 공격측 앞 칸부터 한 번씩 공격한다. 첫 생존 방어 유닛이 막는다. 최초 교전에서 카드별 코인을 굴리고, 코인으로 HP가 0이 된 방어 유닛이 있으면 다음 생존 방어 유닛을 찾는다.
5. 공격 피해, 생존 반격, 전장 이탈과 승리 판정을 처리한다. 살아남은 방어 유닛은 다음 공격도 막지만 코인을 다시 굴리지 않는다. 방어 유닛이 없으면 레벨만큼 덱을 소각한다.
6. 양측 소울을 회복하고 유닛 유지비·부족분 소각·승리 판정을 처리한다. 다음 라운드를 시작하거나 체험판 턴 제한 결과를 확정한다.

물리 피해에는 DP가 적용되고, `HP -2`처럼 능력치를 직접 바꾸는 마법에는 DP를 차감하지 않는다. 현재 전투의 DP는 각 물리 타격에 적용되는 방어력이며 공격을 맞았다는 이유만으로 소진되지 않는다. AP-DP를 HP에서 빼는 산식은 [2015년 플레이어 가이드](https://m.blog.naver.com/jlplace/220468684977)에 명시되어 있지만, 여러 번 방어할 때 DP가 소진되지 않는다는 별도의 공식 문장까지 확보한 것은 아니다. 코인식은 덧셈·뺄셈·곱셈·대입을 구분한다. 예를 들어 아이언타워의 `DP =2C1`을 `DP +2C1`로 바꾸지 않는다.

## 수록 카드와 효과

정확한 96종 ID·이름·DB 수치·출처·효과 매핑은 [`selection.json`](../Tools/Data/ClassicCards/selection.json), 런타임 정의는 [`ClassicCardData.cs`](../Games/FantasyCards/Assets/Game/Core/ClassicCardData.cs)가 기준이다. 안정 ID는 `fm_<원작 DB ID>`다. 지형은 속성마다 2종, 특수기술 없는 정적 유닛은 속성마다 8종, 마법은 속성마다 2종을 선정했다. 미지원 특수기술을 설명만 남긴 채 기본 유닛으로 대체하지 않았다.

| 실제 수록 분류 | 카드 수 |
|---|---:|
| 프리 | 67 |
| 커먼 | 12 |
| 언커먼 | 11 |
| 레어 | 1 |
| 스페셜 | 5 |

코드는 DB의 12등급 명칭을 지원하지만 현재 96종의 실제 등급은 위 **5종**이다. 등급은 원본 `RareType` 값이며 비용에 따라 임의로 높이지 않았다. 랭크 변형과 희귀 등급은 별도 개념이다. 전체 레벨 분포는 0/1/2/3/4/5/6/7에 각각 14/23/18/10/9/7/9/6종이다. 0레벨 지형도 LP 비용은 있으며, 유닛은 전체적으로 레벨 1–7을 제공한다. 금속의 선정 유닛은 확인한 단순 후보 범위에서 레벨 1–6이다.

모든 선정 마법은 원본의 1배틀 지속과 사용 시점을 반영한다. 아래는 실제 효과의 요약이며 원본 카드와 수치 대조는 선정 JSON을 따른다.

아이템 12종은 원본이 순수 AP/DP/HP 가감으로 정의된 카드다. 만능/장비/마법/야수 및 복합 능력의 장착 조건을 검사하며 유닛이 떠나면 장비도 함께 버린다. AP 대입·별 고정값·미지원 특수기술을 가진 원작 아이템은 단순 가감으로 바꾸지 않고 선정에서 제외했다.

## 기본 덱과 체험전

네 덱은 모두 **지형 16 / 유닛 24 / 마법 6 / 아이템 4 = 50장**이다. 각 덱은 두 속성, 낮은 레벨부터 상위 유닛까지의 실제 카드 곡선을 사용한다. 네 아바타와 네 덱의 16가지 조합을 선택할 수 있으며 아바타에 따른 전투 능력 차이는 없다.

| 덱 ID | 표시 이름 / 속성 | 추천 아바타 |
|---|---|---|
| `forest` | 숲과 빛 · 생명의 전열 | 리리아 |
| `knights` | 불과 금속 · 강철의 진격 | 카엘 |
| `tides` | 물과 암흑 · 심연의 파도 | 세린 |
| `stars` | 대지와 빛 · 황금의 성채 | 노아 |

상대는 `garden` 숲의 첫 결투(숲·빛/리리아), `lake` 심연의 시험(물·암흑/세린), `observatory` 강철의 관문(불·금속/카엘)이다. AI도 동일한 자원·준비·코인 규칙을 사용한다. 자기 손패와 공개된 유닛만 보고 합법 행동을 선택하며 상대의 숨은 마법이나 미래 코인 결과를 읽어 행동하지 않는다. 체험전 종료 검증은 인간 플레이 난이도나 균형이 확정됐다는 뜻이 아니다.

## 결정론·저장·검증

셔플과 코인만 `BattleState.randomState`의 Xorshift32를 소비한다. 정수 선택은 rejection sampling이며, UI 연출·도감·hover는 RNG를 바꾸지 않는다. 같은 콘텐츠·규칙·저장 상태·행동은 같은 사건 순서와 결과를 만든다.

schema 3은 덱/손패/지형/버림/유닛/장비/예고 마법, LP·7색 소울·총소울, 준비 단계, 셔플 사용 턴, 카드 사용 기록, 코인 상태, 선택 아바타·덱·상대, RNG와 로그를 보존한다. 카드 인스턴스 보존, 기본 덱 구성, 같은 카드 제한, 유닛/장비/전열, 자원과 이벤트 일치를 검사한다. 이전 schema 2를 새 규칙으로 조용히 해석하지 않는다. 저장 슬롯과 플랫폼 경계는 [구현 문서](FantasyCardsImplementation.md)를 따른다.

2026-10-26 외부 .NET 하네스는 **73/73 통과, 실패·건너뜀 0**이다. 이 수는 카드 규칙과 공용 저장·서사 회귀를 함께 실행한 전체 결과이며 순수 카드 테스트만의 수가 아니다. 카드 검사는 4덱 × 3상대 × 3seed의 36개 대전을 끝까지 진행하며 매 행동의 JSON 복원·RNG·사건·카드 보존을 대조했다. 이 36개 대전은 12–25턴, 63–143행동에서 모두 자연 종료했다. 셔플·소울 지불·AP/DP/HP·물리 피해·마법 순서·숨김 예고·장비 조건·유지비·손상 저장·턴 제한 종료 저장도 검사했다.

실행 근거는 `Artifacts/TestResults/Core/core-tests.trx`다. 턴 제한 종료에서 마지막 준비 기록과 턴 번호가 어긋나는 문제를 재현한 수정 전 TRX는 `Artifacts/Validation/FmExpansion/CoreIterations/turn-limit-before-fix.trx`에 보존했다. 실제 Unity JsonUtility·씬·Web·Windows·공개 URL 결과는 [Validation.md](Validation.md)와 각각의 실행 아티팩트로 별도 판정한다.
