# 판타지마스터즈 공식 BGM 시작·장면 전환

이 문서는 이전 공식 외부 플레이어의 구현 이력이다. 현재 정상 플레이에는 외부 플레이어를 사용하지 않는다. 최신 원작 녹음의 로컬 발췌·전투곡과 출처는 [FmFidelityMusic.md](Research/FmFidelityMusic.md)를 따른다.

2026-10-26 소스 개정. 원 제작사 SOUND-I의 공식 SoundCloud 플레이어를 사용한다. 원곡 파일을 추출·다운로드·변환하거나 다른 BGM을 원작 음악으로 대신 재생하지 않는다. 출처와 공개 원곡의 범위는 [FmRevivalSources.md](Research/FmRevivalSources.md)를 따른다.

## 지연 원인과 변경

이전 구현은 iframe 하나에 `widget.load()`를 호출해 로그인→로비→덱→전장마다 새 곡을 다시 불러왔다. 첫 입력도 Unity canvas에만 연결해, 로딩 화면이나 모바일 시작 버튼을 먼저 눌러도 음악을 시작하지 못했다.

현재 템플릿은 로그인234910360, 로비234910359, 덱234910362, 전장234910353의 공식 iframe 네 개를 페이지를 열 때부터 유지한다. `single_active=false`로 재생 중인 곡이 다음 플레이어의 준비 때문에 자동 정지되는 것을 막는다. 장면 변경은 준비된 플레이어를 선택하며 `widget.load()`나 iframe 주소 변경을 하지 않는다. 다음 플레이어가 실제 `PLAY`와 `getCurrentSound()` 응답을 보내고 그 응답의 원곡 ID를 확인할 때까지 이전 곡을 유지한다. 빠른 장면 이동·음소거 이후 도착한 이전 응답은 적용하지 않는다.

현재 곡은 공식 플레이어 `READY`에서 즉시 재생을 시도한다. 나머지 곡은 음량0으로 미리 재생을 시도하고, 실제 `PLAY_PROGRESS`가 진행된 뒤 일시 정지·처음으로 이동해 준비한다. 브라우저가 시도를 거절하면 페이지의 신뢰된 첫 포인터·터치·키 입력에서 다시 시도한다. Unity 로딩 중의 **시작 · 원작 BGM 듣기**, 모바일 방향 안내 버튼, 게임 화면의 첫 조작이 모두 같은 경로를 사용한다. 음악을 명시적으로 끈 상태는 첫 입력이 해제하지 않는다.

이는 브라우저 자동재생 정책의 우회가 아니다. 사용 이력이 허용하는 환경에서는 입력 없이 시작할 수 있고, 새 브라우저에서는 첫 실제 입력이 필요할 수 있다. 공식 제공자의 네트워크·버퍼링·정책 때문에 모든 기기에서 일정한 밀리초 지연이나 항상 무음 없는 전환을 보장하지 않는다. 준비되지 않은 다음 곡의 버퍼링 중에는 이전 곡을 이어 재생한다. 연결 오류 시 공식 플레이어를 열어 직접 확인할 수 있다.

## 설정과 관측

`FmOriginalMusic.SetScene/SetMuted/SetVolume` API를 유지한다. 장면 메시지에는 음소거·음량을 다시 설정할 권한이 없다. 푸터의 설정은 브라우저 저장소 `FC.originalMusic.muted`·`FC.originalMusic.volume`에 저장한다. Unity의 `FmOriginalMusic.Muted`·`Volume` 읽기는 현재 푸터 상태를 반환하고 PlayerPrefs에 반영한다. 브라우저에 저장값이 없는 첫 실행에서는 기존 Unity PlayerPrefs 값을 받아온다. Unity 설정 창은 표시 시 이 속성을 읽는다. 공식 외부 플레이어가 없는 네이티브 실행의 기존 동작을 유지한다.

기존 `#fm-music-toggle`·`#fm-music-status`와 `data-playback`·`data-track-id`·`data-position-ms` 관측 계약을 유지한다. 곡ID·제목·제작자는 선택하려던 곡이 아니라 활성 위젯의 실제 `getCurrentSound()` 응답이다. 위치는 활성 위젯의 실제 `getPosition()`/`PLAY_PROGRESS` 값이며, 전환 중 다른 iframe의 진행이나 늦은 콜백은 반영하지 않는다. 활성 곡을 바꿀 때 이전 위치를 지우고 새 실제 위치 응답을 기다린다.

추가 `data-requested-scene/track-id/at-ms`는 요청 상태다. `data-play-event-at-ms`는 수락된 플레이어가 보낸 실제 `PLAY` 시각, `data-play-at-ms`는 곡 확인 후 전환을 적용한 시각이다. `data-latency-ms`는 요청에서 전환 적용까지의 시간이다. 모두 같은 페이지의 `performance.now()`를 사용한다. 미리 음량0으로 재생 중이던 플레이어는 장면 선택 이전의 `PLAY`를 보유할 수 있으므로, 이 경우 전환 적용 시각과 실제 요청 이후 위치 진행을 함께 확인해야 한다. 숨겨진 준비 플레이어의 `PLAY`를 현재 장면의 출력으로 세지 않는다. `FirstGameOriginalMusic.getDiagnostics()`는 각 플레이어의 준비·실제 재생 이벤트·활성 여부를 확인하는 읽기 전용 값이다.

## 검증 범위

`node --test Tools/Validation/test-fm-original-music.cjs`는 실제 HTML 안의 컨트롤러를 추출해 지연된 공식 위젯 응답 모델로 실행한다. 14개 테스트에서 iframe 사전 생성, 페이지 전체의 신뢰된 입력, 다음 곡 확인 전 이전 곡 유지, 빠른 장면 이동, 잘못된 실제 곡ID, 진행 후 준비 완료, 늦은 콜백·위치 무시, 음소거·음량 저장과 장면 메시지의 설정 보존을 검사한다. 준비·전환을 위한 정지 명령 직후 아직 `PAUSE` 응답이 오지 않았을 때 돌아와도 새 `play()`를 요청하는 회귀도 포함한다. 이는 네트워크 지연·브라우저 정책·실제 출력의 측정이 아니다.

실제 빌드에서는 새 브라우저 컨텍스트의 페이지 열기→로딩 중 첫 시작 조작→로그인 재생, 준비 이후 로비→덱→전장 및 빠른 왕복을 따로 측정한다. 각 요청과 해당 공식 위젯의 실제 `PLAY`, 실제 `getCurrentSound()`의 SOUND-I 곡ID, 증가하는 위치를 함께 기록한다. 푸터 음소거→장면 변경→Unity 설정 표시, Unity 음량 변경→푸터 관측도 확인한다. 실제 실행 수치와 청취 범위는 최종 [Validation.md](Validation.md)의 해당 실행 근거를 따른다.

`Tools/Validation/revival-smoke.py`의 카드 경로는 로딩 중 보이는 시작 버튼을 실제 입력으로 누르고, `fm-music-observer.js`의 수동 관측으로 요청·실제 전환 시각을 수집한다. `provider-audio-*.json`에는 선택된 ID와 별개인 실제 위젯의 `getCurrentSound()` 재확인, 증가하는 실제 위치, 전체 수동 관측 타임라인, 첫 신뢰 입력→실제 `PLAY`/전환 적용 및 요청→실제 `PLAY`/전환 적용 수치를 보존한다. 원곡이 이미 준비 재생 중이던 경우 실제 `PLAY`가 요청보다 이르다는 사실을 별도로 기록하고 음수 지연을 만들지 않는다. 공식 서비스 실패는 원본 오류를 보존하며 `--require-provider-audio`를 지정했을 때 검증 실패로 처리한다.
