# 판타지마스터즈 Nativity: 실제 장비 확인과 공격 전 파괴

개정 `fm-nativity-2026-11-02`. 2,646종 출전 카드·15,350종 보존 원본·27개 자유 연습 덱, 카드 ID·원본 그림·종횡비, 소유·재화·schema3/기존 슬롯을 유지한다. 이번 변경은 원작에서 확인한 두 동작을 현재 전투에 연결하는 범위이며, 종료 직전 클라이언트 전체 복구를 뜻하지 않는다.

## 확인한 근거와 실제 누락

[2005 공식 오프라인 매뉴얼](https://web.archive.org/web/20051101013311id_/http://www.fantasymasters.co.kr:80/Guide/Manual/tutorial6.asp)은 준비 완료 전 카드 소각을 허용하고 소울을 사용한 지형을 예외로 둔다. [보존 직접 조회 기록](../Tools/Research/FmFidelity/hand-discard-official-evidence.json)에 원문 확인 문장·URL·응답 해시가 있다. 준비 중 실제 장착 아이템 한 장을 소각하는 Core API는 Reprise에서 이미 만들었지만, Restage의 Presentation에는 `UnitState.equipment`를 읽는 코드가 없어 실제 장착 카드의 목록·상세·개별 소각으로 들어갈 방법이 없었다. 수치만 바뀌고 장비 자체는 확인할 수 없는 누락이었다.

[2016-09-11 보존 공식 FAQ734](https://web.archive.org/web/20160911090258id_/http://www.fantasymasters.co.kr/HelpDesk/FAQ_view.asp?category=106&Nowpage=1&faqNo=734)는 실제 아이템을 스웜에게 장착하는 예와 “HP … 0 이하가 될 시 유닛은 파괴됩니다”라는 규칙을 제시한다. [이번에 재검토한 텍스트](../Tools/Research/Restage/faq734-2016-text.txt)는 Restage에서 새로 확보한 응답이며, Nativity에서 네트워크 재조회했다고 주장하지 않는다.

[보존 공식 FAQ736의 특수기술 안내](../Tools/Research/FmRenewal/faq736-text.txt)는 리크리에이트를 “AP 1 이상 공격시, 아군 소각장 맨 위의 아이템 1을 자신에게 이동시켜 장착한다”라고 설명한다. [기존 실제 출전 데이터](../Tools/Data/ClassicCards/selection.json)의 리크리에이터 `4021320946`과 다크크로스 `11030241241`는 이 경로에 도달할 수 있는 실제 원본이다. 현재 엔진에서 자동 장착된 음수 HP 장비가 공격 유닛의 체력을 0으로 만들더라도, 장착으로 늘어난 AP를 먼저 피해로 적용하고 이후에 파괴했다. 이는 확인한 HP0 파괴 규칙과 맞지 않았다.

## 실제 장비 목록과 개별 소각

전장 유닛을 두 번 누르거나 길게 누르면 현재 유닛·장착 아이템 화면을 연다. 원본 카드 전체를 비율대로 표시하고 유닛의 AP/DP/HP는 실제 인스턴스 값을 사용한다. 장착 원본을 누르면 기존 상세로 들어가며 돌아오면 같은 유닛의 장착 목록으로 복귀한다. 전장으로 돌아가기는 기존 이동·배치·공방 흐름을 유지한다.

아군 장비의 소각 버튼은 `CanDiscardField(0,itemInstanceId)`의 실제 준비·소유 검사 결과를 따른다. 사용하면 같은 `DiscardField` 경로로 실제 장비 한 장을 소각하고 비용은 돌려주지 않는다. HP 장비를 잃어 유닛도 파괴될 수 있다는 결과를 화면에서 알린다. 준비를 마친 상태의 장비는 소각할 수 없다. 상대의 필드 유닛·이미 공개된 장비는 확인만 할 수 있고 상대 손패·덱 내용·미공개 예약 마법은 이 화면에 가져오지 않는다. 버튼 표시를 우회한 낡은 콜백도 Core의 소유·준비 검사를 통과해야 한다.

장착 목록의 화면 구성·터치 입력은 리마스터 편의 UI다. 원작 클라이언트의 동일한 장비 창을 복구한 것으로 소개하지 않는다. 현재 유닛당 아이템 두 장 상한 역시 기존 체험 구현의 제한이며 원작의 예외 없는 장착 상한이라고 확정하지 않는다.

## 공격 전 HP0 처리

공격 전 자동 장착을 처리한 직후 실제 HP를 확인한다. HP가 0이면 그 유닛은 공격 피해·후속 공격 기술·반격을 진행하지 않는다. 호출자의 기존 파괴 처리에서 유닛과 장비를 같은 원본 인스턴스로 한 번씩 소각하고, 실제 파괴 기술과 다음 턴 흐름은 계속 처리한다. 별도 코인이나 UI 난수를 소비하지 않는다. HP가 남는 자동 장착과 AP0에서 발동하지 않는 원문 조건은 유지한다.

리크리에이터의 현재 카드 원문에는 “원래의 능력치로 이용합니다.(기호제외)”도 있다. 보존 공식 목록은 이동·장착을 확인하지만 모든 기호 예외와 조합을 설명하지 않는다. 이번 수정은 현재 지원하는 가감 장비의 실제 HP0에 대한 동작을 바로잡는다. 대입·고정·상하한 장비 전체나 그 문구의 모든 예외를 새로 복구했다고 주장하지 않으며, 미지원 장비를 단순 가감 카드로 바꾸어 출전시키지 않는다.

## 검증 범위

`NativityEquipmentTests` 세 검사는 자동 장착으로 HP0인 유닛의 공격 금지·장비와 유닛의 단일 소각·이전 저장의 동일 재개·중간 프레임 깊은 복사·같은 RNG, HP가 남는 경우의 실제 공격, AP0의 원문 발동 제한을 확인한다.

`NativityEquipmentSmokeTests` 두 Native 검사는 실제 장비 목록의 완전한 원본과 실제 카드 숫자, PC/터치 목록, 준비/소유에 따른 소각 제한, 개별 소각과 HP 장비 해제로 인한 실제 파괴, 자동 장착 HP0 사건의 물리 TMP와 독립 Core 프레임·최종 JSON을 확인한다. 기존 Restage의 실제 장착→앞면 코인→피해 수치 검사는 별도 Nativity 복사본에서 유지한다. Native 입력은 실제 콜백을 호출하는 결정적 진단 fixture이며 브라우저 포인터나 자연스러운 한 판 플레이를 대신하지 않는다.

실행·테스트·Unity·브라우저·빌드·배포와 결과의 유일 소유자는 `remaster_release`다. 새 실행 근거는 [Nativity 검증 폴더](../Artifacts/Validation/Nativity)에 남긴다. 이 문서의 구현 설명은 실행 통과 기록이 아니다.
