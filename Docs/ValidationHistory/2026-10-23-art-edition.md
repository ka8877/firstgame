## 실제 화면 검수와 수정

카드 타이틀·도감·상세·덱·전투를 1920×1080, 1280×720, 844×390 및 휴대폰 레터박스에 해당하는 693×390 크기로 확인했다. 네 개의 2×2 atlas는 카드마다 627×627 원화를 제공하며 카드 효과·안정 ID는 유지한다. 구형 atlas는 원본을 Archive에 보존하고 런타임 Resources와 카드 참조에서 제거했다. 작은 화면은 네 장씩 표시하는 도감/덱과 별도 전투 배치를 사용한다.

밝은 타이틀 원화와 글자가 겹치는 문제를 실제 캡처에서 발견했다. 두 게임의 uGUI 그라데이션 메시가 생성되도록 수정하고 좌측/하단 대비를 보강했다. 카드 검사는 실제 메시와 알파도 확인한다. 서사는 타이틀 복귀 시 게임 카메라·HUD를 비활성화하고 전환 중 중복 화면을 제거했다. 대화 종료 뒤 3인칭 카메라가 빠르게 안정되도록 블렌드도 조정했다. 수정 후 native 테스트와 캡처를 다시 생성했다.

첫 실제 Web 720p에서는 손패 이름 영역의 높이 부족으로 다섯 카드 이름이 모두 잘리는 문제가 발견됐다. 이름/하단 영역을 넓히고 네 해상도에서 저장된 모든 손패와 실제 버튼 이름·보이는 글리프·경계·최소 글자 크기를 대조하는 회귀 검사를 추가했다. 기존 720p 검사는 원화 비율만 확인했으므로 이 결함을 잡지 못했다. 수정 후 native 19/19와 Windows/Web를 재실행했다. 원래 실패와 수정 전 출력은 보존한다.

모바일 실제 터치 검사는 저장 복원 뒤 정찰자 배치까지 도달했으나, 작은 전장 슬롯의 이름·능력치가 생략되는 별도 제품 결함을 찾았다. 손패는 정상이었고 배치 비용·손패 감소도 처리됐지만 전장에는 원화만 표시됐다. 작은 전장 칸을 왼쪽 초상과 오른쪽 정보 두 행으로 바꾸고 실제 유닛 배치 뒤 네 해상도에서 이름·능력치·상태·코인 글리프의 전체 표시·경계·최소 12px를 검사했다. 수정 후 native 19/19와 Windows/Web 빌드를 통과했으며 실제 캡처에서도 모두 표시된다. 같은 OCR 영역은 이전 결함 화면을 거부했다. 카드 브라우저 세 화면을 이 새 빌드로 다시 실행해 모두 통과했다.

서사 첫 PC Web 검사는 이동·저장 등 26개 기능을 통과했지만 원본 검수에서 PC에도 모바일 패드가 표시되는 것을 발견했다. WebGL의 가상 Touchscreen 존재만으로 입력 방식을 판정하던 부분을 실제 브라우저 touch point와 coarse pointer 조합으로 바꾸고 PC/모바일의 조작 안내·패드 표시 분기를 별도로 검사한다. 모바일의 작은 조작 안내 글자도 확대했다. 693×390 및 자막 110% 설정의 실제 native 캡처로 글리프·줄 넘침을 확인하고 10/10 검사를 다시 통과했다. 이전 26개 결과를 최종 수정 빌드의 통과로 재사용하지 않는다.

새벽의 길은 캐릭터의 연속 의복·얼굴·머리카락·수염과 환경을 교체하고 URP에서 세 단계 음영·그림자·림·가는 실루엣 잉크를 적용했다. 캐릭터별 SkinnedMesh 1개, 기존 FBX GUID·10본 리그·BasicIdle·원점·발바닥 높이를 보존했다. 초기 의복 소실과 머리카락/수염 문제는 실제 Blender 렌더로 찾아 수정했다. 최종 실제 Unity 화면에서 단일 몸체·셀 음영·대화 초상·타이틀 대비를 확인했다.

실제 Unity 캡처는 `Artifacts/Screenshots/{FantasyCards,PathOfDawn}`이며 각 PNG 옆에 엔진·해상도·렌더러를 기록한다. `Tools/Art/Previews/ToonDawn_*.png`는 별도의 Blender 렌더다. 원화 자체와 실제 플레이 화면을 같은 검증으로 취급하지 않는다. 모델은 개선한 개발 자산이며 원화와 동등한 최종 3D 품질이나 사용자 승인을 주장하지 않는다.

최신 검증 계획과 결과는 [시각·브라우저 검증](VisualValidation.md), 배포 운영은 [웹 체험판](WebPlaytest.md)을 따른다. PC 1280×720·1920×1080과 모바일 가로 844×390의 두 게임을 각각 실행하며 최신 보고서는 `Artifacts/Validation/VisualWeb/{Desktop720,Desktop1080,Mobile844}/{Game}/report.json`에 둔다. 이전 WebSmoke 결과는 2026-10-20 기록이며 새 빌드의 통과 근거로 사용하지 않는다.

브라우저 검사는 새 컨텍스트에서 실제 마우스/키보드 또는 터치 이벤트로 조작한다. 카드 지형 전개, 서사 이동·대화, 저장·페이지 새로고침·이어하기를 검사하고 원본 캡처·OCR·IndexedDB 저장 키·렌더러·정확한 빌드 파일 해시를 남긴다. UnityCache의 전송 취소는 같은 탐색의 실제 config.dataUrl, GET 및 재검증 로그, 정상 재로드/저장 복원이 함께 확인된 경우만 구분한다. 예상하지 못한 네트워크 오류는 통과로 바꾸지 않는다.

화면 판독 중 OCR의 한글·숫자 오독과 제목 crop 경계 부족을 발견해 원본을 보존하고 영역·언어·일반 전처리를 보완했다. 카드 1080p 제목은 완전한 글리프를 직접 검수한 뒤에도 OCR이 ‘빛’을 ‘빚’으로 읽었다. 이 경우에 한해 `Tools/Validation/VisualReferences`의 검수된 원본과 **같은 실행 파일 해시·화면 크기·영역·decoded RGB 픽셀의 완전 일치**를 확인하며 OCR 통과와 별도로 기록한다. 다른 글자나 빌드, 한 픽셀의 변화도 이 방식으로 통과하지 않는다. 관련 오프라인 검사 13/13이 통과했다.

## GitHub 소스 검증

원화·모델을 포함한 첫 개정은 main 커밋 `68337c9`로 업로드했고, 손패 글자·PC/터치 판정 수정은 `98a48b3`으로 추가 업로드했다. 모바일 전장 정보 수정은 `18b85b0`으로 추가 업로드했으며 세 커밋 모두 GitHub의 규칙/저장 CI가 성공했다. 별도의 새 클론에서 로컬 Git LFS 설정·pull·checkout 후 원화/모델/글꼴 **30개**의 실제 바이트 SHA-256이 LFS OID와 모두 일치했다. 처음에는 객체 다운로드 후에도 작업 파일이 포인터로 남아 있어 로컬 LFS 필터를 설치하고 checkout한 뒤 확인했다. 근거는 `Artifacts/Validation/GitHub/source-clone.json`이다. 이는 파일 복원 확인이며 새 PC의 Unity import나 새 클라우드 작업 복원을 검사한 것은 아니다.

## 환경과 확인하지 않은 범위

Unity 6000.3.26f1 / Windows Mono·WebGL, Blender 4.3.2, .NET 8.0.426을 사용했다. CLI는 현재 로그인되지 않았지만 Personal 라이선스가 유효하며 실제 Editor 실행·컴파일·테스트가 성공했다. CLI 인증 상태와 Editor 라이선스를 분리하도록 진단을 수정했다. 초기 로그인·자격·약관 동의를 반복 요청하지 않았다. 환경 상태와 원래 온보딩 결과는 `Tools/Environment/validation.json` 및 `validation-2026-10-20.json`에 구분한다.

Xvfb/Mesa llvmpipe 또는 SwiftShader는 소프트웨어 GPU다. 검사 시간은 목표 PC/휴대폰 성능이나 인터넷 로딩 시간으로 해석하지 않는다. 실제 Android/iPhone·Safari, Windows 플레이어, 전체 전투를 포인터로 완료하기, 전체 걷기/충돌 경로, 게임패드·음향, 전체 브라우저 종료 후 복귀, Web↔Windows 저장 이동은 별도 실기 검수가 필요하다. 실제 표정·걷기·입모양·정밀 UV/텍스처와 플랫폼별 LOD도 후속 제작 범위다.

외부 53건과 native 29건에는 같은 규칙을 다른 환경에서 확인하는 항목이 있으므로 고유 기능 수로 합산하지 않는다. native UI 테스트는 실제 Play Mode에서 공개 버튼 콜백과 가상 Input System 입력을 사용하며 브라우저의 실제 포인터 검증을 대신하지 않는다. 기본 리그의 BasicIdle 유지가 걷기 애니메이션 완성을 뜻하지 않는다.

산출물은 네 가지 플레이어 ZIP, `FirstGame-UnitySources.zip`, `FirstGame-ValidationEvidence.zip`과 `Deliverables.sha256`이다. 최신 보고서와 캡처, 이전 실패 이력은 보존하고 실제 통과한 파일만 배포한다.
