# 예수님의 일생 — 복음서 학습 여정

2026-10-26 사용자 요청에 따라 시간 여행자·가상 선택·기억 회귀 중심의 이전 서사에서, 예수님을 주인공으로 복음서 기록을 따라가는 학습 게임으로 방향을 바꾼다. 탄생에서 시작해 공생애·수난·부활·승천까지 확장한다. 이전 Ink 원문과 저장은 보존하며 새 진행 상태와 혼용하지 않는다.

## 이번에 구현하는 첫 구간

탄생의 도입은 누가복음 2장의 성경 구절을 읽는 세 장면이다. 직접 이동하는 첫 구간은 열두 살 예수님의 성전 방문이다. 아기 예수님에게 소년의 보행을 적용하지 않는다.

| 구간 | 인용 본문 | 진행 |
|---|---|---|
| 베들레헴의 탄생 | 눅 2:6–7 | 탄생 도입 첫 페이지 |
| 큰 기쁨의 소식 | 눅 2:10–11 | 도입 두 번째 페이지 |
| 마음에 간직한 말씀 | 눅 2:19–20 | 도입 세 번째 페이지 후 소년 시점으로 전환 |
| 유월절의 예루살렘 | 눅 2:41–43 | 성전 문에서 말씀 읽기 |
| 선생들 가운데 | 눅 2:46–47 | 선생들이 있는 곳으로 이동해 말씀 읽기 |
| 내 아버지 집 | 눅 2:48–50 | 부모와 만나는 구역에서 말씀 읽기 |
| 나사렛으로 | 눅 2:51–52 | 귀환의 문에서 말씀 읽고 첫 여정 완료 |

총 7개 읽기·16개 절을 직접 인용한다. 누가복음 2:1–5, 8–18, 21–40, 44–45의 연결은 요약·문맥 안내로 제공하며 해당 구절 전체를 모두 장면화했다고 주장하지 않는다. 기록되지 않은 성전 마당의 정확한 배치, 인물 외모, 걷는 경로와 상호작용 지점은 학습을 위한 시각 구성이다. 성경에 없는 질문·답변을 예수님의 직접 발언으로 창작하지 않는다.

`GospelReading.Text`는 직접 인용, `Reference`는 본문 위치, `Context`는 작성한 문맥 요약이다. 인용과 요약을 화면에서도 나누어 표시한다. `CurrentReading`은 이동 중에도 현재 목표의 구절을 제공하고, 읽기 확인을 거쳐야 다음 목표로 진행한다. 잘못된 순서의 상호작용으로 구절을 건너뛸 수 없다. 읽은 본문 식별자는 말씀 기록에 한 번씩 순서대로 남는다.

## 본문과 출처

- 역본·번역자: **『성경전서 개역한글판』, 대한성서공회**.
- [대한성서공회 누가복음 2장, HAN 역본](https://www.bskorea.or.kr/bible/korbibReadpage.php?version=HAN&book=luk&chap=2).
- [대한성서공회 저작권 관련 FAQ](https://www.bskorea.or.kr/bbs/board.php?bo_table=copyright_faq&wr_id=5), 「『성경전서 개역한글판』은 저작권 사용허가없이 사용 가능한가요?」(2017-10-27): “『성경전서 개역한글판』의 저작재산권 보호기간은 50년이 경과되어 저작권료 지급없이 사용 가능합니다.” 동일 안내가 요구하는 성명표시권·동일성유지권을 따라 역본·번역자를 표시하고 본문을 보존한다.

본문은 공식 사이트의 **주 본문**을 기준으로 했다. 개역개정·웹 디자인·성경 낭독 녹음은 가져오지 않는다. HTML의 인명/지명 태그만 없애고 태그 경계의 공백을 정리했으며 옛 표기와 어휘를 현대어로 고치지 않았다. 2:49의 “내 아버지 집”과 2:51의 “말”은 주 본문을 사용하고, 숨겨진 대안 번역 각주를 본문에 합치지 않았다.

`Tools/Data/Gospel/luke2-selected.json`에 공식 URL, 수집 UTC, 응답 SHA-256, 각 절과 추출 규칙을 보존한다. `python3 Tools/Data/Gospel/verify-readings.py`는 네트워크 없이 이 독립 스냅샷과 C#의 직접 인용 7개·16절을 비교하고 `Artifacts/Validation/GospelJourney/scripture-verification.json`을 만든다. 이는 본문 일치 검사이며 게임의 화면·움직임·성능 통과를 의미하지 않는다. 배포용 출처 표시는 `Tools/Data/Gospel/SCRIPTURE-NOTICE.txt`와 `GospelCatalog.Attribution`을 사용한다.

## 진행·저장 계약

순수 C# `GospelJourney`가 `Prologue → Exploring ↔ Reading → Completed`를 소유한다. 성전 목표 ID는 `temple-gate → teachers → parents → nazareth-gate`이며, 장면이 가까운 거리의 실제 상호작용을 확인한 뒤 해당 ID를 전달한다. Core는 Unity 좌표계나 입력 API에 의존하지 않는다. 화면과 움직임은 상태를 읽고 요청만 보낸다.

`GospelSave` 내부 버전은 schema **1**, 콘텐츠 **gospel-0.1.0**이다. 공통 저장 봉투의 게임 ID는 **gospel-journey**, 전용 슬롯은 **gospel-journey-v1**이다. 이전 `path-of-dawn`/`galilee-0.1.0` 저장은 이 슬롯의 여정으로 자동 해석하거나 덮어쓰지 않는다. 목표·읽은 말씀의 순서·장면 상태·위치 유효성을 함께 확인한 뒤 복원한다. 손상·미지원 버전은 현재 진행을 바꾸기 전에 거부한다. 버전 정보가 빠진 `{}`도 새 게임 저장으로 받아들이지 않는다.

위치 저장은 x/z ±100, y −5…30 범위의 유한 수, 방향은 0…360 미만이다. 이동·중력·충돌·거리 판단·카메라는 Unity 쪽 책임이며 저장에 필요한 마지막 유효한 위치만 전달한다. 나중의 전투 행동은 별도 시스템으로 추가하되 현재 학습 구절의 진행이나 성경 기록의 결과를 임의로 바꾸지 않는다.

`Tools/Validation/Tests/GospelJourneyTests.cs`는 읽기 순서·잘못된 목표·읽기 중 저장·모든 도달 가능한 단계의 JSON 복귀·위치·미지원/손상 상태·이전 슬롯 보존을 확인한다. 실제 3D 표현·발 접지·조작감과 브라우저 저장의 검수는 별도 네이티브/플레이어 실행 결과로 기록한다.
