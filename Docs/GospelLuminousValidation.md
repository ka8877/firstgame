# 빛을 따라 걷는 2D 여정 검증

현재 개정은 `gospel-luminous-2026-10-28`, 릴리스 프로필은 `luminous`다. 사용자의 Ori·Unity Lost Crypt 참고 화면에 따라 예수님 게임을 실제 2D 횡스크롤·다층 배경·관절 인물·2D 조명으로 다시 구성한다. 판타지마스터즈는 기존 `fm-restoration-2026-10-27` 공개 파일과 미리보기 23개를 바이트 그대로 보존하며 새 카드 빌드나 새 카드 검사를 주장하지 않는다.

## 현재 실제 근거

- Core 검사 **145/145**, 누락·건너뛰기0. `Artifacts/Validation/Luminous/Core/core-tests.trx`에 새 결과가 있다. 기존 schema1의 좌표 공간 필드 없는 저장, 새2D 좌표·등잔 왕복, 알 수 없는 좌표 공간 거부·기존 상태 보존을 포함한다.
- Unity Personal 라이선스는 현재 활성 상태다. CLI 계정 세션 부재와 Editor 라이선스를 구분했으며 재로그인이나 새로운 약관 동의는 필요하지 않았다.
- 초기 가져오기는 사라진 `/tmp` 패키지 캐시를 가리키는 생성 해석 캐시 때문에 실패했다. 원본 로그를 보존하고 생성 `Library/PackageManager`만 보관한 뒤 커밋된 manifest/lock의 같은 패키지를 다시 받았다. 다음 실제 컴파일에서 URP17.3의 별도 2D 런타임 어셈블리 참조와 읽기 전용 조명 API를 확인해 수정했다.
- `NativeDraft04`의 실제 Unity 준비와 새 PlayMode 검사2개는 통과했다. 실제2D공간·이동·점프·소지품·등잔·저장/Boot새로불러오기를 확인했으나, 첫 실제 원본에 검은 그림 조각·지면 띠·가려진 타이틀 버튼이 보여 시각 승인을 하지 않았다. 이 초기 통과를 최종 외형 검증으로 재사용하지 않는다.
- `NativeDraft05`의 통제된 SRP Batcher 끄기 검사는 검은 조각을 해결하지 못했다. UI 정렬과 두 줄 제목은 수정됐고, `NativeDraft06`은 구름의 수평 경계·앞쪽 돌 배치와 메시용 천 셰이더를 수정한 실제 원본을 남겼다. 정상 좌측 이동·점프·저장 복원과 성전까지 실제 달리기 입력을 포함한 검사2개는 통과했다. 새 성전 구도와 좌측 천은 정상이나 숲의 일부 검은 조각이 남아 최종 시각 승인은 보류했다.
- `NativeGameView07`은 RenderTexture 요청이나 Canvas 모드 변환 없이 실제 GUI GameView를 정상 렌더링하고 `ScreenCapture` 원본을 남겼다. 같은 검은 조각이 관찰돼 캡처 방식만의 문제로 분류하지 않는다. 현재 미완성 화면을 최종 공개판으로 배포하지 않는다.
- 이후 실제 GUI의 `NativeLightDiagnostic09`에서 전역 조명만 남긴 통제 화면은 정상이었고, 로컬 조명의 노멀맵만 끈 화면에는 검은 조각이 남았다. 정확한 노멀 품질·사용하지 않는 그림자 끄기·유효한 Point 각도 설정만으로는 해결되지 않았다. 이 진단 화면을 출시 외형으로 사용하지 않는다.
- 지원되는 Freeform 로컬 조명으로 바꾼 `NativeCircle12`에서는 검은 반쪽 인물·돌 조각이 사라졌지만 목표 지점의 작은 검은 원이 남았다. 같은 목표 조명을 원본 SoftGlow 스프라이트 쿠키 경로로 바꾼 `NativeCookie13/title-original.png`의 실제 정상 GameView에서는 이 원도 사라졌다. 루트가 해당 원본을 직접 확인했다. 원본 그림·HDR·정확한 노멀 조명·색·위치는 유지했으며, 모든 로컬 조명을 같은 지원 경로로 정리한 최종 화면은 후속 NativeFinal14에서 별도로 확인했다.
- 모든 공간 조명과 손의 등잔을 검증된 Sprite 쿠키로 통일한 **NativeFinal14 2/2**, 누락·건너뛰기0. 실제 키 입력 이동·좌측 의상·점프/착지·등잔 장착·저장 후 Boot 재로딩/이어하기·성전까지 달리기를 확인했다. 루트가 현재 타이틀·월드·좌측·소지품·복귀·성전 원본6장을 직접 보고 검은 결함이 사라졌음을 확인한 뒤 소스를 고정했다. 현재 입력1418개와 SHA256 지문은 해당 시도 `source-inputs.json`에 있다. 이는 정적 원본 검토이며 사용자 미적 승인·실기기 성능 측정이 아니다.
- Windows 빌드 뒤 URP가 저장한 사전 필터·전역 활성 리소스 목록 때문에 첫 Web 후보의 입력에서 두 생성 설정이 달랐다. 해당 성공 후보와 원래 입력을 비배포 자료로 보존했다. Unity 종료 뒤 세 URP/전역 에셋을 Native 고정본과 SHA256이 같은 원본으로 복원했으며, 새 빌드 래퍼는 이후 같은 생성 부작용을 변경 전·후 기록과 함께 복원한다. 입력 파일을 해시 대상에서 빼거나 과거 실행에 새 소스를 덮어 연결하지 않았다.
- 최종 Windows(`PlayerFinal15`)·Web(`PlayerFinal16`) 빌드는 각각 오류0, 경고1로 성공했다. 현재 소스·Native·두 플레이어 입력1418개와 지문 `28042dce…`가 모두 일치한다. 경고는 사용하지 않는 별도 Unity Pipeline 패키지의 설정 부재이며 URP2D 비활성화 경고가 아니다. 실제 Web 런타임5개는 **47,048,497바이트**다. Unity의 Web 요약 크기는 템플릿만 집계하므로 전체 다운로드 크기로 사용하지 않는다.
- `BrowserFinal17`의 첫 입력 시도는 Unity 로더 완료 직후 아직 남은 기본 스플래시에 클릭해 검증 대상 화면으로 가지 못했다. 기계적으로 통과한 Desktop 원본도 직접 보고 거부했으며, 원래 보고서·화면·하네스를 `EarlyReady17`과 거부 기록에 보존했다. 로더 뒤 일반 스플래시 종료를 기다리는 4초만 추가하고 같은 최종 런타임을 다시 실행했다.
- 새 **Desktop720 16/16·Mobile844 16/16** 검사를 완료했다. 실제 클릭/키/터치로 시작·이동·등잔 장착·저장·전체 페이지 재로딩·이어하기·성경 본문 열기를 수행했다. 현재 원본은 실제 복귀한 숲·장착 등잔과 말씀 패널을 보여 준다. 각각 분리된 음악 경로의 실제 WebAudio PCM 표본16개, RMS 약0.048/0.044와 2.27초 진행도 기록했다. 직접 스피커 청취나 실물 휴대폰 검증을 뜻하지 않는다.
- 루트가 두 새 브라우저 보고서의 현재 원본14장을 직접 확인하고 전체 런타임5개의 해시와 함께 승인했다. `Root/local-browser-critical-review.json`에 실제 검토 범위와 한계를 기록했다. 공개 미리보기는 승인된 Desktop 월드 원본을 바이트 그대로 사용한다.

현재 첫 원본과 로그는 `Artifacts/Validation/Luminous/NativeDraft04`에 보존한다. 공개 URL 결과는 완료한 뒤 추가한다. 개발 중 파일이나 이전 공개판의 결과를 현재 배포 통과로 소개하지 않는다.

## 환경과 저장 공간

새 빌드·캐시는 작업 전용 `/tmp/firstgame-luminous-*`에 둔다. `HOME`, 라이선스 위치, TLS와 프록시 검증을 유지한다. 두 프로젝트의 생성 Library를 `/tmp`로 옮길 때 모든 실제 파일 바이트를 대조했다. 공간 확보는 기존 ZIP 안의 같은 경로·바이트로 복구 가능한 과거 확장 플레이어 파일811개에만 적용했으며 원본 ZIP·고유 소스·미일치 파일·검증 증거를 보존했다. 상세 복구 경로와 해시는 `zip-covered-expanded-player-reclamation.json`에 있다.

## 범위와 한계

Lost Crypt의 실제 공개 샘플 그림·Unity Companion License 안내와 새로 제작한 예수님/성전 그림을 구분한다. 상용 Ori 원본 코드나 전체 게임을 복구한 결과가 아니다. 실제 고대 경관의 측량 복원이나 인물 외모의 역사적 확인도 아니다. 말씀 직접 인용과 학습용 설명·소지품을 구분하고, 새 시각 장면 진입으로 읽지 않은 성경 본문을 읽음 처리하지 않는다.

소프트웨어 GPU·Chromium 터치 에뮬레이션을 실제 휴대폰/Windows 하드웨어 성능, 사람의 스피커 청취 또는 사용자의 미적 승인으로 표현하지 않는다.
