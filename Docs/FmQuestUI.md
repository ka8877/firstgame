# 판타지마스터즈 싱글 플레이 수집 UI

`fm-quest-2026-10-30`은 기존 원본 카드·공방 규칙·2,646종 출전 카드·27개 연습 덱·15,350개 원본 도감을 보존하면서, **기본 덱 받기 → 보유 덱으로 싱글 대전 → SP 보상 → 카드팩 구매·개봉 → 보유 덱 편집**을 실제 진행으로 연결한다. 이번 UI의 실제 실행·공개 반영 상태는 별도 Quest 검증 기록을 따른다. 소스 구현이나 이전 Chronicle의 통과를 새 실행 결과로 소개하지 않는다.

## 첫 시작과 소유

타이틀 **게임 시작**은 싱글 프로필을 연다. 처음에는 빛·물·불·숲·금속·대지·암흑의 기존 단일 속성 50장 덱 중 하나를 고른다. 선택과 **이 덱을 무료로 받기**는 별개이며, 실제 `TrySelectStarter`가 성공하고 프로필 저장이 끝난 뒤에만 카드 50장과 환영 SP가 표시된다. 무료 덱을 다시 받아 다른 속성까지 중복 획득할 수 없다. 다른 속성의 확정 50장 세트는 상점에서 SP로 구한다.

**내 카드 보관함**은 `OwnedCount`가 있는 카드만 보여 준다. 덱 편집의 `+`는 보유 수량·원작 카드별 덱 한도·전체 50장을 모두 확인한다. 저장과 새 싱글 대전 시작 시 Core가 덱의 원작 구성 및 소유 수량을 다시 검증한다. 구입·개봉한 카드도 같은 보유 목록과 편집기에 나타난다. 카드 그림은 새 프레임으로 재조립하지 않고 원본 인쇄 전체와 종횡비를 유지하며, 누르면 기존 전체 상세와 크게 보기를 이용한다.

기존 **자유 연습**은 별도 메뉴다. 이곳에서는 27개 기존 덱과 기존 편집 덱을 사용할 수 있고, 아직 소유하지 않은 카드도 기존 방식으로 연습한다. 보유 덱으로 진행하는 싱글의 SP를 지급하지 않는다. 보유 카드·SP·카드팩을 기존 자유 연습 전투/편집 덱 슬롯으로 덮어쓰지 않는다.

실제 모바일 브라우저의 616×346 게임 화면에서 덱 수량 버튼의 짧은 `+ / −` 글자가 누락되는 것을 원본 캡처로 확인했다. 약 14px인 내부 글자 영역에 일반 최소 글꼴 크기가 줄 높이보다 크게 적용돼 TMP가 한 줄을 표시하지 못한 사례다. 두 버튼의 라벨에만 기존 `UiCanvasTextSize.ConfigureCard(27)`의 한 줄 크기 맞춤을 적용했다. 버튼의 위치·행 높이·동작과 공유 글꼴 helper는 변경하지 않는다. 수정 후 실제 화면 확인 결과는 새 검증 기록을 따른다.

## 싱글·보상·상점

대기실은 기존 판마의 금속 프레임·왼쪽 목록·오른쪽 프로필/소울 구체 체계를 사용한다. 새 오른쪽 영역은 실제 프로필의 SP, GP 0, 보유 카드 장수/종수를 읽는다. GP 버튼과 멀티플레이 버튼은 추후 추가 안내만 연다. 실제 결제·가상의 온라인 방·이용자·채팅·매칭은 제공하지 않는다.

싱글 시나리오는 기존 네 개 실전 과제를 순서대로 열고, AI 대전은 기존 세 상대와 보유 덱으로 겨룬다. 대전 시작에서 Core가 생성한 티켓과 실제 전투가 연결된다. 전투를 끝내면 실제 Core 정산 결과를 결과창에 표시하고 SP를 저장한다. 첫 시나리오 승리 보너스는 총 보상 안에 포함돼 두 번 더하지 않는다. 같은 완료 화면의 재생성이나 완료 저장의 재로딩은 보상을 다시 지급하지 않는다. 진행 중인 대전은 이어하기 또는 보상 없는 포기를 선택할 수 있다.

상점에는 SP 부스터, 한국 시간 하루 한 종류를 고르는 무료 A/B/C, 속성 확정 기본 덱 탭이 있다. 상품 상세에서 가격·구성·등급 확률·보장 칸을 읽고 구입한다. 구매와 개봉은 별도 동작이며, 구매 후 나가도 아직 열지 않은 카드팩은 보관함에 남는다. 다시 접속해서 같은 구매 건을 개봉하며 새 결과를 재추첨하지 않는다. 개봉이 저장된 뒤에만 짧은 카드 뒷면 연출과 실제 획득 원본을 보여 준다. 같은 카드가 여러 장이면 획득 수량을 합쳐 표시한다.

SP·GP 명칭과 무료 A/B/C의 존재는 원작 자료에 근거한다. 현재 환영 보상·가격·획득 확률·내용·임무 보상은 현재 싱글판의 구성이다. 이를 종료 직전 원작 서버의 경제 수치나 과금 상품을 복구한 것으로 소개하지 않는다. 상세 수치는 [경제 Core 계약](FmQuestEconomy.md), 조사 근거는 [이번 참고 자료](Research/QuestReferences.md)를 따른다.

확보한 원본 인쇄 표기와 현재 출전 DB의 등급 분류가 일치하지 않는 사례가 있다. 실제 개봉에 나타난 **라바서커**는 원본 인쇄에 `UNIQUE`가 보이지만 현재 DB의 등급 값은 업그레이드다. 원인을 시기별 변경이라고 확인한 자료는 없으므로 추정으로 설명하거나 Core 등급을 임의로 바꾸지 않는다. 개봉 결과는 원본 인쇄와 카드 이름을 그대로 보여 주고 추가 영역에는 **획득 수량·보유 수량만** 표시한다. 새 외곽선도 중립적인 얇은 선을 사용한다. 상품 확률 설명에는 현재 출전 카드의 등급 분류를 사용하며 일부 인쇄 표기와 다를 수 있음을 알린다.

## 원작 셔플과 전투 표시

공식 보존 자료 `tutorial2_1`은 **손패 여섯 장을 덱에 넣고 섞은 뒤 순서대로 다시 받으며, 해당 준비 단계에서 카드 사용 전 한 번 가능**하다고 설명한다. 이미 이 방식을 구현한 Core를 임의의 한 장 교체로 바꾸지 않는다. 당시 방 옵션에는 4턴·6턴·무제한·없음이 있지만 현재 종료 직전 설정이라고 확인할 자료는 없으므로 새로운 제한이나 SP/LP 비용을 만들지 않는다.

기존 임의의 전면 1.45초 카드 흔들기 화면은 제거했다. 실제 전장과 지형을 유지하면서 원본 뒷면 6장이 손패 영역에서 오른쪽 덱으로 돌아가고, 덱에서 순서대로 돌아오는 약 0.94초 연출을 표시한다. 첫 배분은 덱에서 받는 과정만, 시작 손패 교체와 준비 중 셔플은 회수 과정을 포함한다. 실제 새 손패와 코인·전투 RNG는 이미 Core에서 결정된 것을 읽으며 연출은 상태나 RNG를 바꾸지 않는다.

Chronicle의 위·아래 전열, 원본 오른쪽 아래 AP/DP/HP 숫자 위치, 양측 다섯 칸의 사각 코인 판정창, 실제 확률·변화량과 하단 지형은 유지한다. 세부는 [후기 전장](FmChronicleUI.md)과 [확인한 원작 자료](Research/FmChronicleSources.md)를 따른다. 원 개발 소스나 최종 클라이언트를 회수한 결과로 표현하지 않는다.

## 저장과 검증 관찰

프로필은 `fantasy-quest-profile-v1`, 보유 덱은 `fantasy-quest-deck-v1`, 해당 싱글 전투는 `fantasy-quest-battle-v1`을 사용한다. 이전 `fantasy-battle-classic-v3`와 `fantasy-deck-classic-v3`는 자유 연습에 보존한다. 기존 전투 내보내기 화면에는 자유 연습 전투만 옮기는 기능임을 표시한다. 싱글 수집 상태는 현재 브라우저·기기의 로컬 저장이다.

화면의 각 경제 변경은 변경 전 스냅샷을 보관하고 `PersistentSaves` 저장이 실패하면 메모리 상태를 되돌린다. 프로필과 전투의 두 저장 사이에서 전투 파일 저장에 실패한 경우에도 대전 티켓이 보존되고, 보상 없는 포기 후 새로 시작할 수 있다. 손상된 프로필·덱 저장을 원본 초기화로 감추지 않는다.

새 실행 검사를 위한 읽기 전용 관찰값은 `QuestHasStarter`, `QuestSp`, `QuestGp`, `QuestStarterDeckId`, `QuestOwnedCount`, `QuestDeckCards`, `QuestProfileSnapshot`, `QuestCurrentScreen`, `QuestCurrentTicketId`, `IsQuestBattle`, `QuestUnopenedPackCount`, `QuestRevealedPurchaseId`, `IsClientShuffleActive`다. 프로필과 목록은 복사본 또는 읽기 전용으로 노출한다. 이 관찰값이나 설계 문서는 일반 포인터·터치 입력 및 새 Unity/Web 원본 검토를 대신하지 않는다.
