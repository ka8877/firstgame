# 별빛의 서약 — 첫 결투 구현과 검증 안내

## 구성

- `Assets/Game/Core`: Unity 비의존 규칙, 상태, 16종 카탈로그, 결정론 난수, 규칙 기반 AI.
- `Assets/Game/Data`: 카드/RuleSet의 ScriptableObject 제작 브리지. `Resources/Data/Cards`의 16종을 안정 ID로 검증하여 런타임 정의에 반영한다. `Resources/Data/Rules`에서 규칙을 복제한다. 에디터 제작 에셋이 아직 없으면 코드 카탈로그를 기본값으로 쓴다.
- `Assets/Game/Presentation`: `FantasyCards.Presentation.FantasyCardsApp`. uGUI/TMP 화면, Input System UI/ESC, Cinemachine 전장 카메라, 1.2초 Timeline 카메라 도입(`BattleRevealClip`), 사건 애니메이션, Shared 저장 어댑터 호출. 코인 애니메이션에는 난수를 사용하지 않는다.
- `Assets/Game/Tests`: Unity EditMode NUnit 테스트. 별도 .NET 하네스로 Core와 동일 테스트를 실행할 수도 있다.
- `Assets/SmokeTests`: 실제 PlayMode로 진입하는 에디터 테스트. Boot 씬과 UI 콜백, 저장 후 새 앱 인스턴스의 이어하기, 결과/재도전을 검사한다.
- 부모 프로젝트의 Editor bootstrap이 씬, URP, Build Profile, ScriptableObject 파일과 메타를 관리한다.

## 플레이 순서

1. 타이틀에서 카드 도감의 ‘이전/다음’으로 네 장씩 원화를 살펴보고 덱 구성에서 `-/+`로 24장의 기본 덱을 조정한다. ‘덱 저장’을 누르면 다음 실행에도 유지된다.
2. ‘새로운 결투’를 시작한다. 튜토리얼의 고정 seed는 731029이다. 같은 덱으로 재도전하면 같은 출발 조건을 얻는다.
3. 아래 손패의 지형을 선택한 뒤 ‘지형 전개’를 누른다. 넓은 화면은 왼쪽, 작은 가로 화면은 손패 위에 조작 버튼이 있다. 여명/조류 자원은 중앙 하단에 표시된다.
4. 유닛을 선택하고 빛나는 빈 아군 칸을 누른다. 비용이 부족한 경우 칸이 활성화되지 않는다.
5. 마법/장비는 손패에서 선택한 뒤 해당 아군 또는 적 유닛 칸을 누른다. 카드 설명과 ‘확대 보기’로 원화와 효과를 읽는다.
6. ‘공격 단계’ → 행동 가능한 아군 → 적 유닛 또는 위쪽 상대 생명 버튼으로 공격을 선언한다. AI의 방어가 기록된다.
7. 상대 공격 때는 준비된 아군 칸을 눌러 가로막거나 ‘가로막지 않기’를 누른다. 공격하지 않은 유닛을 방어에 남기는 판단이 필요하다.
8. 코인 앞/뒷면, 최종 공격력, 방어구 차감과 반격을 넓은 화면의 오른쪽 기록 또는 작은 화면의 ‘전투 기록’ 버튼에서 확인한다. 효과 재생 중 입력은 잠긴다.
9. 승패 화면에서 재도전하거나 덱을 다듬는다. 모든 유효한 행동 뒤 자동 저장하며, 별도 저장 버튼과 타이틀 이어하기도 제공한다.
10. 타이틀 ‘저장 내보내기 / 가져오기’에서 JSON envelope 문자열을 다른 기기로 옮긴다. 가져온 저장은 버전/무결성/코어 상태를 검증한 뒤 교체한다.

## 테스트와 실행 범위

2026-10-23 일러스트/UI 개편 후 Unity 6000.3.26f1 네이티브 검사 **19/19 통과, 실패·건너뜀 0, 프로세스 exit 0**. 기존 규칙/저장/승패 흐름 18건을 유지하고 도감·확대·작은 화면 검사 1건을 추가했다. 실제 UI에서 네 장짜리 영웅 도감 → 확대 → 덱 편집 → 새 전투를 이동한다. 844×390 및 웹 16:9 영역에 해당하는 693×390에서 주요 버튼의 화면상 가로·세로가 44px 이상인지, 손패 이름/지형 전개 문구가 생략 없이 렌더되고 12px 이상인지 검사한다. 모든 원화 UV가 자기 셀 안에 있고 화면 비율과 맞는지, 명암 그라데이션의 실제 렌더 메시/알파가 존재하는지도 검사한다. 갤러리/크기 변경은 전투 저장과 난수를 바꾸지 않아야 한다.

새 캡처는 `Artifacts/Screenshots/FantasyCards/01-title.png`부터 `13-battle-phone-letterbox.png`까지다. 07은 영웅 도감, 08은 확대 원화, 09는 모바일 확대, 10은 모바일 덱 편집, 11은 844×390 전투, 12는 1280×720 전투, 13은 693×390 전투다. 캡처는 실제 Unity URP와 TMP 결과이며 브라우저 포인터 테스트는 별도다. 작은 화면에서 타이틀 왼쪽/하단 명암, 카드 이름과 비용, 주요 조작의 표시를 직접 확인했다.

`BattleEngineTests`는 정의/덱 장수, 지형의 턴당 제한과 다음 턴 생산, 비용 부족 시 무변경, 소환 대기, 방어 중 저장·복원 뒤 다음 코인/로그 일치, 여러 seed의 양측 AI 전투 종료/결정론, 승패/치명 피해, 잘못된 저장의 거부를 검사한다.

검사 결과는 `Artifacts/TestResults/FantasyCards/EditMode.xml`이며, 규칙/실제 JsonUtility 왕복 테스트 15건과 실제 PlayMode UI 흐름 4건으로 구성된다.

- 지형 테스트: 타이틀 → 새 결투 → 지형 전개 → 저장 → Boot 씬 제거/재생성 → 이어하기로 동일 상태를 확인한다.
- 결과 테스트: 양측이 `BattleAi`의 합법 행동으로 완료한 승리(seed 2)와 패배(seed 1)를 실제 JsonUtility/공용 저장 서비스로 저장한다. 새 앱의 타이틀 이어하기에서 결과 문구와 상태 일치를 확인한 뒤, 재도전 콜백이 새 seed 731029 전투와 난수 상태를 만들고 Timeline 입력 잠금을 해제하는지 검사한다. 이 테스트는 결과 복귀 흐름 검증이며, 화면에서 전투 전체를 마우스로 플레이한 검증은 아니다.
- 저장 실패 테스트: 유효한 저장 A가 있는 상태에서 실제 지형 사용으로 현재 전투 B를 만들고 저장 백엔드에 쓰기 실패를 주입한다. 타이틀 콜백과 실제 Input System Escape 입력 모두 전투 B·엔진 인스턴스·오류 화면과 이전 저장 A 원문을 유지하는지 검사한다. 쓰기를 복구한 뒤 저장 재시도와 새 Boot 앱의 이어하기가 B를 복원하는지 확인한다. 같은 저장 성공 가드는 결과 화면의 덱 편집 이동에도 적용한다.
- 네 UI 테스트는 격리된 메모리 저장 백엔드를 사용하며 실제 버튼 콜백을 호출한다. 물리적 포인터 hit-testing과 기기 간 저장 이동은 별도 인수 검증 대상이다. 씬 로드/제거의 완료, 활성 씬, 앱 인스턴스 교체를 명시적으로 검사한다.


2026-10-23 새 원화/UI를 포함한 최종 Windows x64 빌드 성공: 125,886,962 bytes, 증분 BuildReport 시간 12.872초, 오류 0, 경고 1, 프로세스 exit 0. 경고는 개발용 Pipeline의 RuntimePipelineConfig가 없는 기존 안내이며 게임 실행에 의존하지 않는다. 빌드 후 GraphicsSettings와 현재 Quality 5가 DesktopURP GUID `4d2e1fa2feef2604a9367d90953bb6be`를 유지했다. 실제 Windows OS에서 Player를 실행한 검증은 별도다.

2026-10-23 최종 WebGL 빌드도 프로세스 exit 0으로 성공했다. BuildReport 시간 4분 31.635초, 오류 0, 경고 4(Pipeline 1건과 큰 TMP 메서드 분리 컴파일 안내 3건)다. 빈 출력 폴더에 해시 이름의 loader/framework/data/wasm 네 파일을 생성했고 HTML의 네 참조가 실제 파일과 일치함을 확인했다. 이번 Unity BuildReport의 `Bytes: 7134`는 index.html 크기만 집계하므로 전체 용량으로 사용하지 않는다. 별도 파일 검사 `OutputFiles.json`의 HTML+4파일 합은 **40,962,237 bytes**이며 각 파일 SHA-256을 기록했다. 빌드 뒤 GraphicsSettings와 현재 Quality의 DesktopURP 복원도 확인했다.

Web 빌드·실제 브라우저 포인터/저장 검증의 최신 결과는 루트 `Docs/Validation.md`를 기준으로 한다.

외부 순수 C# 테스트는 Unity의 렌더링·패키지 가져오기·웹 저장을 대체하지 않는다. 실제 기기 60fps, 다양한 화면 비율, 키보드 전용 탐색과 전체 전투의 포인터 조작은 별도 검증해야 한다.

## 아트 현재 상태와 남은 작업

- 2026-10-23 새 오리지널 일러스트: `cards-01-terrain`, `cards-02-heroes`, `cards-03-magic`, `cards-04-relics`의 2×2 atlas 네 장. 각 1254×1254, 카드 한 셀 627×627이며 이전 4×4 atlas보다 셀당 픽셀 수가 4배다. 성인 정찰자·수호자·창기사·요정·기록자와 지형/마법/장비를 기존 16 stable ID 순서대로 연결한다. `title-hero.png`는 1672×940 타이틀 원화다. 원화 생성 기록은 아트 매니페스트를 따른다.
- `ProjectSetup`이 Texture2D, NPOT 크기 보존, clamp, mipmap 없음으로 가져오고 16개 `CardAsset.illustration`의 셀을 검증한다. 카드의 수치·ID·저장 콘텐츠 버전은 변경하지 않는다. 이름/비용/능력/프레임은 원화와 분리된 UI다.
- `IllustrationCrop`은 각 Sprite.rect 안에서 원화 비율을 유지하며 표시 영역을 채운다. 인접 셀이 보이지 않도록 반 픽셀을 안쪽으로 잡는다. 확대 화면은 정사각에 가까운 큰 원화를 보여 주며 손패·유닛 칸은 일부를 크롭한다.
- 타이틀 영웅 원화, 네 장씩 넘기는 도감/덱, 큰 확대 보기, 여명 골드·조류 청록 프레임과 남색 패널을 사용한다. 캔버스 폭 1400 미만 또는 가로 비율 1.95 초과에서는 compact 전투 조작 행을 쓴다. 600px 미만 높이에서는 작은 글자의 크기를 픽셀 기준으로 보정한다. 모바일 가로 대응이며 세로 화면 전용 배치는 이번 범위 밖이다.
- 구 4×4 원화는 `Assets/Art/Archive/card-atlas.png`에 원본과 메타를 보존한다. 모든 에셋 GUID 참조가 제거된 것을 확인했고 Resources 폴더에서 제외하여 새 Player에 함께 넣지 않는다.
- Blender `Assets/Art/Generated/StarfallArena.fbx`: 3D 전장 초안. 씬의 인스턴스 이름은 `StarfallArena`로 한다. 누락 시 런타임이 임시 원형 전장을 만든다.
- 유닛의 3D 캡슐 말은 임시 표식이다. 개별 리깅 캐릭터나 최종 미니어처로 보고하지 않는다.
- 짧은 사인파 차임은 임시 효과음이다. 최종 카드 이동/천/금속/지형의 계열별 사운드로 교체해야 한다.
- 카드가 이동하는 물리적 궤적, 전장 타격 VFX, 세부 전투 카메라, 수집 보상, 캠페인과 추가 덱은 후속 작업이다.
- 가변 RuleSet에 맞춘 전체 레이아웃 확장, 세밀한 덱 균형, 긴 기록 스크롤, 세로 화면 접근성과 키보드 전용 탐색을 다음 품질 단계에서 확인한다.

완료 기준: Unity에서 에셋 누락 없이 첫 전투를 끝내고, 양쪽 방어 선택/승패/재도전/이어하기/웹→PC 저장 이동을 조작 검증한 뒤 실제 1080p Windows와 웹 프로파일로 캡처·성능 기록을 남긴다.
