# 별빛의 서약 — 카드 체험판 구현과 검증 안내

## 현재 구현 범위

40종 카드(지형 8·유닛 16·마법 9·장비 7), 독자적 리더 4명과 고유 기술, 24장 기본 덱 4종, 체험 결투 3전을 제공한다. 지형 생산·유닛 공방·방어 선택·코인·규칙 기반 AI를 유지하며 실제 덱 셔플, 시작 손패 1회 교체, 마우스 설명과 터치 상세를 더한다. 판타지마스터즈의 지형·공방과 섀도우버스의 리더 중심 표현을 참고하지만 원작의 모든 규칙·콘텐츠를 재현한 게임으로 소개하지 않는다. 근거와 우리 설계값은 [카드 규칙](FantasyCardsRules.md)을 따른다.

이 문서는 소스의 구현 계약이다. 새 버전의 native·Windows·Web·공개 URL 검증 완료 여부는 [검증 기록](Validation.md)이 기준이며, 이전판의 통과 수·캡처·빌드 크기를 이번 버전의 증거로 사용하지 않는다.

## 구성과 상태 소유권

- `Assets/Game/Core`: Unity 비의존 규칙, 결정론 난수, `CardCatalog` 40종, `DemoCatalog` 리더/기본 덱/상대, AI. 셔플·손패 교체·기술 비용과 사용 가능 여부를 포함한 실제 상태의 단일 원본이다.
- `Assets/Game/Data`: 카드/RuleSet의 ScriptableObject 제작 브리지. `Resources/Data/Cards`의 40종을 안정 ID로 검증해 런타임 정의에 반영한다. 에디터 제작 에셋이 아직 없으면 코드 카탈로그를 기본값으로 쓴다.
- `Assets/Game/Presentation`: `FantasyCardsApp`과 partial `FantasyCardsDemoFlow`. uGUI/TMP·Input System·Cinemachine·Timeline, 리더/덱/상대 선택, 셔플 시각 효과, 시작 손패와 리더 기술 상세, `UiCardHover`, Shared 저장 어댑터 호출을 담당한다. 연출·설명·도감은 게임 난수를 소비하지 않는다.
- `Assets/Game/Tests`: 규칙·저장 결정론 EditMode 테스트. 별도 .NET 하네스는 동일 Core를 검증하지만 실제 렌더링이나 플랫폼 저장을 대신하지 않는다.
- `Assets/SmokeTests`: Boot 씬·실제 UI 콜백·새 앱의 이어하기·승패/재도전·저장 실패·시각 글리프 검사. 실제 포인터 hit-testing과 공개 URL 검사는 별도다.
- `Assets/Editor`: 씬·URP·Build Profile·40개 CardAsset·리더 초상·폰트와 메타 생성 및 검증.

## 리더·기본 덱·세 결투

리더와 덱은 자유롭게 조합한다. 각 기술은 내 준비 단계에 해당 속성 2를 지불해 턴당 한 번 사용한다. 효과 적용·대상 선택은 Core가 처리하며 UI는 비용과 사용 불가 사유를 보여 준다.

| 리더 | 기술 | 기본 덱의 테마 |
|---|---|---|
| 리리아 · 숲의 궁수 | 꽃바람 화살: 남은 생명이 가장 낮은 적 유닛에 피해 2, 적 유닛이 없으면 적 리더에 피해 1 | 꽃바람의 숲: 저비용 궁수·요정과 공격 강화 |
| 카엘 · 태양 기사 | 태양의 서약: 모든 아군 유닛 공격 +1, 아군 유닛 필요 | 백화 기사단: 방어·기사·장비 |
| 세린 · 물결 마녀 | 호수의 숨결: 리더 생명 3, 모든 아군 피해 1 회복, 회복할 피해 필요 | 달호수의 노래: 제거·회복·후반 해룡 |
| 노아 · 별의 기록자 | 별의 인도: 카드 1장 뽑기와 여명 1, 덱과 손패 여유 필요 | 별술사의 서고: 뽑기·두 속성 자원·코인 |

세 상대는 `1장 · 꽃바람의 초대`(리리아), `2장 · 달호수의 시험`(세린), `3장 · 별빛의 서약`(노아)다. 상대 선택 화면에서 각각 도전할 수 있고 승리 후 다음 결투로 이어진다. 승리 표시는 기기별 PlayerPrefs에 보존한다. 장기 캠페인·수집 보상·온라인 대전은 현재 범위에 포함하지 않는다.

## 실제 UI의 플레이 순서

1. 타이틀의 카드 도감에서 네 장씩 10페이지를 살펴보고, 덱 구성의 `-/+`로 24장 편집 덱을 만든다. 지형 최소 4장·유닛 최소 6장·동일 카드 최대 4장과 속성 자원 조건을 Core로 검증한다. `덱 저장`은 전투 저장과 별도다.
2. `새로운 결투` → 네 리더 중 선택 → 네 기본 덱 또는 `내 편집 덱 사용` → 세 상대 중 선택 → `덱을 섞고 시작`으로 진행한다. 새 결투마다 새 seed를 만들고 Core가 실제 카드 순서를 섞는다. 약 1.45초의 시각적 셔플 자체는 난수를 소비하지 않는다.
3. 시작 손패 다섯 장을 보고 교체할 카드를 고른다. 기본 덱의 시작 손패는 여명·조류 지형을 포함한다. 최대 다섯 장을 한 번 교체하거나 `이대로 시작`을 누른다. 교체 카드는 새 카드를 뽑은 뒤 덱에 돌려 섞어 같은 카드 인스턴스가 즉시 돌아오지 않게 한다. 교체 결과·남은 순서·교체 종료 상태는 저장에 포함된다.
4. 손패 지형 선택 → `지형 전개`. 한 턴에 한 장이며 이후 턴의 자원을 만든다. 유닛은 손패 선택 후 비용을 낼 수 있는 빈 아군 칸에 배치한다. 소환 대기를 확인한다.
5. 대상이 필요한 마법·장비는 선택 후 적/아군 유닛 칸을 누른다. 뽑기·자원 획득·적 전체 피해 마법은 별도 유닛 선택 없이 사용한다. 카드 설명·확대 보기와 키워드 설명으로 효과를 확인한다.
6. 왼쪽 아래 내 리더 초상을 누르면 현재 덱명·기술·비용·사용 가능 사유를 확인하고 `리더 기술 사용`을 누른다. 전투를 이어 한 뒤에도 저장된 리더와 덱명을 표시한다.
7. `공격 단계` → 행동 가능한 아군 → 적 유닛 또는 상대 리더로 공격을 선언한다. 상대 공격 때 준비된 아군을 눌러 가로막거나 `가로막지 않기`를 고른다. 공격하지 않은 유닛을 방어에 남기는 판단이 필요하다.
8. 코인 앞/뒷면, 최종 공격력, 방어구와 반격은 오른쪽 기록 또는 작은 화면의 `전투 기록`에서 확인한다. 효과 재생 중 중복 입력을 막는다.
9. 승패 화면에서 다음 결투·다시 도전·덱 편집으로 이동한다. 모든 유효 행동 뒤 자동 저장하며 별도 저장 버튼도 제공한다. 재도전 선택 화면의 `내 편집 덱`은 현재 저장한 편집 덱을 뜻한다.
10. 타이틀 `저장 내보내기 / 가져오기`에서 진행 JSON을 다른 기기로 옮긴다. 가져오기는 버전·무결성·Core 상태를 검증한 뒤 적용한다. 편집 덱과 완료 표시·음악 설정은 전투 JSON과 별도다.

마우스를 카드·자원·단계·기술·조작 버튼에 올리면 설명이 나온다. 터치에서는 카드 상세 선택과 길게 누르기를 사용한다. 손패가 여섯 장 이상이면 가로로 스크롤하여 모든 카드를 선택한다. 드래그 도중의 길게 누르기와 화면을 닫은 뒤 남는 설명은 취소한다.

## 저장·재현 계약

내부 `BattleState`는 schema 2, 콘텐츠는 `starlight-0.2.0`이다. Shared 저장/전송 봉투는 schema 1을 유지한다. 새 슬롯 `fantasy-battle-demo-v2`와 `fantasy-deck-demo-v2`는 구 `fantasy-battle`/`fantasy-deck` 파일을 보존한다. 이전 전투는 새 리더·덱·교체 상태가 없으므로 명확히 거부하며 조용히 변환하거나 덮어쓰지 않는다.

전투에는 카드 인스턴스·손패·덱 순서·지형·유닛·장비·버림 카드·RNG·리더 기술 사용·상대·시작 손패 상태를 보존한다. 동일 저장 상태와 동일 행동은 같은 코인과 결과를 만든다. 새 사용자 결투는 고정 seed가 아니며, private `StartBattle(uint)`의 이전 기본 덱 진입은 회귀 테스트 호환용이다.

이어하기는 전투 자신의 카드 영역을 복원하며 독립된 편집 덱 목록을 덮어쓰지 않는다. 예를 들어 덱 A로 시작한 전투를 저장한 뒤 편집 덱 B를 저장했다면, 이어하기는 A를 진행하고 다음 새 custom 결투는 B를 사용한다. 저장 실패 때는 현재 전투·오류 화면과 기존 유효 슬롯을 보존해 실패한 타이틀 이동이 플레이를 유실하지 않게 한다. 가져오기 뒤 이전 엔진의 종료 저장도 차단한다.

## 아트·레이아웃 계약

- 2×2 아틀라스 10장, 40개 슬롯은 좌상→우상→좌하→우하 순서다. 기존 `cards-01-terrain`부터 `cards-04-relics`의 ID 순서를 보존한다. 확장은 `cards-05-sanctuaries`, `cards-06-forest`, `cards-07-tides`, `cards-08-celestial`, `cards-09-spells`, `cards-10-armaments`다.
- 리더 초상은 `Art/portrait-lyria/kael/serin/noa`의 투명 배경 이미지이며 전체 UV를 쓴다. 원화 생성·해상도·출처는 [일러스트](Illustration.md)를 따른다. 인물은 독자적 만화 디자인이며 원작 캐릭터 복제나 상용 수준 품질 보증으로 소개하지 않는다.
- `IllustrationCrop`은 각 셀 안에서 비율을 유지해 표시 영역을 채우며 인접 셀이 보이지 않도록 한다. 수치·글자·프레임·둥근 마스크는 원화와 분리된 UI다. 구 4×4 원화는 `Assets/Art/Archive/card-atlas.png`에 보존하고 Player Resources에 중복 포함하지 않는다.
- 캔버스 폭 1400 미만 또는 가로 비율 1.95 초과에서는 compact 전투 조작 행을 쓴다. 높이 600px 미만에서는 글자 크기를 픽셀 기준으로 보정하고 전장 유닛 정보는 읽을 수 있는 두 행을 확보한다. 1280×720·1920×1080·693×390과 844×390에서 이름·비용·기술·주요 조작의 실제 글리프와 겹침을 확인한다.
- 기존 `StarfallArena.fbx`와 유닛 3D 캡슐은 개발용 전장/표식이다. 개별 리깅 캐릭터나 최종 미니어처로 보고하지 않는다. BGM은 완성 음원을 사용하지만 합성 차임은 개발용 효과음이다.

## 검증과 남은 범위

Core 검사는 40종/네 덱/네 리더·16가지 조합, 세 상대, 기술의 실제 비용·한 턴 제한·실패 시 무변경, 교체 1회·빈 선택 확정·저장 복원, 여러 seed AI 전투 종료/결정론과 손상 저장 거부를 다룬다. Native UI 검사는 새 선택 흐름과 실제 버튼 콜백, 교체·기술·도감·덱·저장 실패·승패·이어하기, 한국어 글리프·터치 영역·아틀라스 경계·난수 불변을 다룬다. 테스트 존재는 실행 통과와 같지 않으며 결과 수치·최종 파일 해시는 [검증 기록](Validation.md)과 해당 아티팩트를 따른다.

Web 인수 검사는 실제 포인터/터치로 리더→덱→상대→셔플→손패 교체→지형/유닛/기술→저장/새로고침을 수행하고, hover·길게 누르기·BGM과 시각적 읽힘을 확인한다. 테스트 내부 상태를 준비한 승패 복귀 검사와 실제 전투 전체를 포인터로 끝낸 검사를 구분한다. Windows 빌드 성공은 Windows 실기 플레이 통과를 뜻하지 않는다.

남은 품질 작업은 개별 전투 VFX·카드 이동·계열별 효과음·미니어처, 세밀한 덱 균형, 세 결투를 넘는 캠페인과 수집 보상, 긴 기록 스크롤·가변 RuleSet 레이아웃, 세로 화면과 키보드 전용 탐색이다. 실제 휴대폰 성능, 완전한 전투의 포인터 조작, 웹→PC 저장 이동과 60fps/플레이 시간은 별도 측정·검증 범위다.
