# 판타지마스터즈 전투 리마스터

현재 작업의 전투 화면·연출 계약이다. 구현과 실제 실행 검증은 구분하며, 최종 실행 결과는 릴리스 담당의 새 검증 기록을 따른다.

## 원작에서 확인한 기준

- 2005년 공식 온라인 안내의 `interface_game.gif`에는 녹색 석재 전장, 양측 다섯 칸, 아래 여섯 장 손패, 오른쪽 소울·덱·소각 정보가 있다. 원본/해시는 `Tools/Research/FmRevival/official-ui-manifest.json`, 이번에 다시 읽은 안내 본문은 `Tools/Research/FmFidelity/official-interface-guide.json`에 있다.
- 공식 오프라인 안내는 공격 준비 → 방어 준비 → 낮은 레벨부터 마법 공개 → 전열 순 공격 → 살아남은 방어 유닛의 반격 → 소울코스트 → 공방 교대를 설명한다. 정확한 원문과 시기 차이는 `Research/FantasyMastersRulesSources.md`를 따른다.
- 원본 안내 우측의 `FLIP / 30SP`와 세 동전은 상대 준비 중 사용하는 별도 SP 미니게임이다. 전투의 코인 판정 창으로 잘못 복제하지 않는다. 이번 전투 코인은 실제 유닛의 공통 코인열을 각 유닛 위에 표시한다.
- 정적으로 조사한 공식 `fmtest.exe`에는 `coin.wav`, `whip.wav`, `spell.wav`, `bom1..4.wav` 등 구분된 소리 파일명이 있지만, 음원 자체가 포함된 리소스는 확보하지 못했다. `archived-launcher-inspection.json`을 따른다. 현재 효과음을 원작 녹음이라고 소개하지 않는다.
- 정상 공개 Naver 플레이어에서 확보한 2017 실제 플레이의 117–123초 원본 프레임은 중앙의 두 카드·가로 코인판정·주황 대각선 베기·피해·파괴·불티를 보여준다. `Tools/Research/FmFidelity/gameplay-video-provenance.json`과 `Research/FmFidelitySources.md`를 따른다. 영상의 `Coin90%` 조건은 확정하지 못했으므로 이를 기본 확률로 넣지 않는다.

## 이번에 고친 전투 표시

기존 화면은 Core가 공방 전체를 계산한 **최종** 전장부터 그린 뒤, 앞뒤 이벤트 최대18개를 약3초의 중앙 문구로 표시했다. 파괴된 유닛은 공격을 보기 전에 사라졌고, 반격·마법의 대상·카드별 덱 소각은 눈으로 따라갈 수 없었다.

새 흐름은 `BattleEngine.BeginPlaybackCapture()`부터 `EndPlaybackCapture()`까지 각 기록 직후의 양측 플레이어 상태를 깊은 복사한다. `BattlePlaybackFrame`은 저장 상태 밖에 있으며, 대상·카드·전열·코인 앞뒤·확정 능력·실제 피해와 함께 사용한다.

`Act`와 AI 행동은 행동 전 상태를 보관하고 Core를 한 번 실행해 결과를 저장한다. 이후 화면만 다음 순서로 재생한다.

1. 지형·유닛·장비 배치와 마법 예고: 해당 위치의 전개 문양, 배치 소리, 배치 후 실제 카드·자원 표시.
2. 마법 공개: 공개 이벤트가 도착한 적 마법만 뒷면에서 얼굴을 보여준다. 예고 때에는 이름·얼굴·속성을 누설하지 않는다.
3. 코인: Core가 확정한 C1…C5 앞/뒤를 차례대로 뒤집고, 누적 앞뒤 열과 최종 AP·DP·HP를 표시한다.
4. 공격·반격: 해당 두 유닛의 원본 카드 표시 복사본을 중앙 위·아래 대전 위치에 놓고 기존 전열을 어둡게 한다. 중앙 카드가 상대 방향으로 움직이고 대상에 주황 대각선 베기·방어 효과, 실제 피해 숫자와 소리를 표시한다. 코인은 중앙 위 가로 패널에서 실제 앞뒤 순서로 뒤집는다. 반격은 별도 이벤트로 따라온다. 그림 복사본은 이벤트 후 모두 제거하며 Core 상태·숨긴 손패·미공개 마법은 바꾸거나 공개하지 않는다.
5. 파괴: 공격 전 카드가 사라지지 않으며, 파괴 이벤트에서 축소·흩어짐을 보여준 뒤 Core 소각장 상태를 그린다.
6. 직접 공격: 덱 위치에 충격을 표시하고, 실제 소각 카드 한 장씩 덱→소각장 이동·불씨·덱 수 감소를 보여준다. 리더 HP를 원작 덱 피해 대신 사용하지 않는다.
7. 드로우·소울코스트·공방 교대: 실제 Core 스냅샷으로 손패·자원·목표를 갱신한다. 상대 드로우는 뒷면만 표시한다.

집계용 기존 `damage` 기록은 전투 기록에 보존하지만 공격/반격의 시각 타격을 중복 재생하지 않는다. 이벤트를 앞뒤만 잘라 버리는 제한은 제거했다.

## 조작과 상태 소유권

- 재생 중에는 `locked`로 카드 사용·준비 완료·메뉴·상세 전환·AI 중복 행동을 막는다. 코루틴 시작 전부터 잠가 같은 프레임의 이중 입력도 막는다.
- `×1 / ×2 / ×4`는 표현 시간만 바꾼다. `끝까지`는 이미 확정된 현재 행동의 나머지 표현만 건너뛴다. 둘 다 카드 판정·RNG·저장 내용을 바꾸지 않는다.
- 화면은 `BattleDisplayState`로 중간 상태를 읽으며 실제 액션 검증은 `engine`을 사용한다. 마지막에는 화면 상태를 해제해 실제 Core 결과를 그린다.
- 전장 칸은 `BindLaneDrop`, 지형 안내 영역은 `BindTerrainDrop`과 연결한다. 실제 판정은 기존 `CanPlay`/`PlayInSlot` 경로를 사용한다.
- 양측 다섯 전열과 손패·오른쪽 정보 배치를 유지한다. 전장 카드에는 원본 카드 전체, 읽을 수 있는 현재 AP·DP·HP, 실제 등급·랭크와 장비 수를 함께 표시한다.

## 시각·효과음 제작

`FmBattleStoneGraphic`은 원작 전장의 녹색 석재 팔레트를 참고한 해상도 독립 표면이다. `FmBattleFxGraphic`은 베기·충격·방어·마법·치유·소각·파괴·전개를 벡터 메시로 그린다. 새 연출이며 원본 클라이언트의 이펙트 리소스를 복구한 결과가 아니다.

`FmBattleAudio`는 샘플을 사용하지 않는 모노44.1kHz 합성 효과음이다. 카드·코인·공격·타격·방어·마법·치유·소각·파괴·단계 소리를 구분한다. 파형 잡음에는 고정된 별도 정수 생성기를 사용하며 게임 RNG를 소비하지 않는다. 제작 기록은 `Tools/Audio/FmFidelitySfx/manifest.json`이다. 원작 BGM 조사·배치는 별도 음악 담당의 기록을 따른다.

읽기 전용 `IsBattlePlaybackActive`, `BattlePlaybackDisplaySnapshot`, `BattlePlaybackEventIndex/Count/Kind`, `BattlePlaybackSpeed`, `LastBattlePlaybackEvents`를 통해 실제 입력 잠금·순서·끝 상태 일치를 검사할 수 있다. 구현 파일의 존재만으로 실제 웹/Unity 실행 검증이나 원작과의 픽셀 단위 일치를 주장하지 않는다.
