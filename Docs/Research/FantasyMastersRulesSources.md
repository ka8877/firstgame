## 상세 소울 계산과 코인 근거

[FM Lunatic 도서관의 소울 FAQ 재수록](https://firestore.googleapis.com/v1/projects/fmdb-bcb70/databases/(default)/documents/livelibrary/2iXWEXsxcHcbKf63Abkn)은 본문에 “출처 : 판마 FAQ 게시판 (웹 아카이브에서 발췌)”, 작성시각 `2013-01-01`이라고 적혀 있다. 원래 FAQ의 정확한 보존 URL은 제공되지 않으므로 **직접 읽은 공식 보존본과 구분한 재수록 자료**다. 여기서는 암흑 지형 10장이 있는 `암흑 10 / 총소울 10`에서 반시 `암흑 1 + 무 1`을 내면 `암흑 9 / 총소울 8`이 된다고 설명한다. 무소울은 다른 색 한도를 임의로 깎는 것이 아니라 보라색 총 사용 가능 소울에서 차감한다. 그러므로 색 한도가 남아도 총소울이 0이면 카드를 더 낼 수 없다.

[Judy의 2015-09-01 가이드](https://m.blog.naver.com/jlplace/220468684977)는 서비스 중 작성된 플레이어 설명이다. 색 비용 4와 빈 구슬 3인 레벨 7 유닛은 **색 한도 4와 총소울 7**이 필요하다는 예시를 든다. 소울코스트는 전 턴에 썼던 소울을 사용 가능량으로 복구하고 손패를 채우는 단계이며, 다음 턴부터 유닛의 빈 구슬 비용은 유지비로 총소울에서 빠진다고 설명한다. 색 소울이 유닛이 죽을 때까지 영구 점유되는 해석이나 미사용 잔량을 계속 저축하는 해석을 뒷받침하지 않는다.

[FM Lunatic의 게임 방식 FAQ 재수록](https://firestore.googleapis.com/v1/projects/fmdb-bcb70/databases/(default)/documents/livelibrary/KPWImW2hsfXBnoVLmxAW)은 `2016-01-01`로 표기되며 공식 조합을 **Deck / 6 turn / 50장**이라고 설명한다. 2005년의 다양한 방 옵션과 시대 차이가 있으므로 이 후기 자료를 근거로 과거 옵션이 없었다고 쓰지 않는다.

코인은 다음 수준까지 확인했다.

- 2015 가이드는 `+3C1 / +C1 / +2C1`인 유닛에 전투 코인 **1개**가 등장한다고 설명한다. AP/DP/HP마다 독립적으로 세 번 굴리는 해석과 맞지 않는다.
- [2004년 공식 포럼의 플레이어 PT 분석 재수록](https://m.blog.naver.com/janglove678/30132101482)은 `+C1`부터 `+C5`의 평균을 `0.5, 1, 1.5, 2, 2.5`로 적고, 하한이 붙은 `▲3 × C3`의 결과를 `3, 3, 6, 9`, 상한이 붙은 `▼5 = 2C3`의 결과를 `0, 2, 4, 5`로 제시한다. 따라서 **Cn이 받는 앞면 수의 범위는 0…n**이며 이진수 `0…2ⁿ−1` 해석과 맞지 않는다. 이 글의 균등 경우 평균은 확률 분포를 증명하는 자료로 사용하지 않는다.
- [2026년 다른 게임과의 비교 글](https://gall.dcinside.com/mgallery/board/view/?id=fanma&no=1022)은 그 게임이 코인 위치를 무시하는 점을 판마와의 차이로 설명한다. 원작의 코인 순서가 중요했다는 보조 근거다. 다른 게임의 화면·튜토리얼을 원작 규칙으로 취급하지 않는다.
- 종합하면 **공통 코인열에서 해당 능력치의 Cn에 필요한 앞 n개의 앞면 수를 세는 구현**이 자료와 일관된다. 다만 “앞 n개”와 화면상 좌우 방향을 직접 정의하는 공식 문장을 찾지 못했다. 이 부분은 자료에 근거한 구현 해석으로 남기며 공식 문장을 확인했다고 주장하지 않는다.

## 등급과 랭크

현재 읽을 수 있는 팬 DB [FM Lunatic](https://fmlunatic.com/)의 공개 `liveappsetting/enumtable`에는 다음 12개 유효 등급이 있다. 이는 DB의 분류 순서이며 **전투력이나 획득 난도의 일렬 순위로 해석하지 않는다**.

| DB 코드 | 표기 |
|---|---|
| FREE | 프리 |
| NORMAL | 커먼 |
| UNCOMMON | 언커먼 |
| RARE | 레어 |
| SPECIAL | 스페셜 |
| UPGRADE | 업그레이드 |
| UNIQUE | 유니크 |
| EVENT | 이벤트 |
| LEGEND | 레전드 |
| ICAJEN | 이카젠 |
| SECRET | 시크릿 |
| EPIC | 에픽 |

별도로 `RankType`는 **N / C / B / A / S**다. [팬 유닛 가이드](https://neginote.wixsite.com/fantasymasters/guide-units)도 등급과 랭크를 구분하고, 같은 이름도 랭크에 따라 수치/능력이 달라질 수 있다고 설명한다. 따라서 카드 정보에서 등급 배지와 랭크를 분리하고, 단순히 비용이 높다는 이유로 높은 등급을 자동 부여하지 않는 것이 자료에 맞다. 카드별 실제 등급은 데이터의 값을 따른다.

[팬 가이드 첫 페이지](https://neginote.wixsite.com/fantasymasters/main-guide)는 11종이라고 쓰며 마지막 명칭도 `에`로 끝난다. [영문 위키](https://en.wikipedia.org/wiki/Fantasy_Masters)는 12종이라고 쓰지만 Basic/Trade/Prize 등을 포함하는 다른 시기의 목록이다. 서로 다른 시기·지역의 목록을 합쳐 원작 전체의 고정 등급 체계라고 단정하지 않는다. 이번 DB 기준의 라벨은 실제 enum을 출처로 삼는다.

## 2차 자료로만 확인한 부분과 미확정 부분

- [나무위키 원작 문서](https://namu.wiki/w/판타지%20마스터즈)는 전투가 끝날 때까지 살아남은 유닛의 능력치가 다음 턴에 원래대로 회복된다고 설명한다. 이 원칙은 현재 읽은 공식 텍스트에는 명시되어 있지 않으므로 **2차 자료** 근거로 표기한다. 영속 강화·상태 효과·전투 중 누적 피해의 모든 예외까지 확인한 것은 아니다.
- 2015 당시 플레이어 가이드는 전투 후 체력을 `HP − (공격자의 AP − 방어자의 DP)`로 설명한다. 매 타격마다 방어력을 빼고 HP만 누적 감소시키는 현재 구현과 일관되지만, 연속 피격 시 DP가 그대로 유지되는지/소진되는지를 직접 대비한 공식 문장은 찾지 못했다. DP를 소진형 방어막으로 변경할 근거도 확보되지 않았다. 해당 산식은 2차 자료에 근거한 구현으로 구분한다.
- 영문 위키는 코인 최대 5개와 동시 0일 때 공격측 승리를 설명한다. 공식 오프라인 텍스트에서 같은 상한·동률 문장을 확인하지 못했으므로 예외 없는 확정 룰로 승격하지 않는다.
- 공식 오프라인 가이드의 직접 공격은 레벨만큼 덱 소각이라고 명확하다. 라이프 모드의 직접 공격 처리와 정확한 시작 라이프는 읽은 본문만으로 충분히 확정하지 못했다. 체험판이 덱 모드 하나를 선택한다면 별도 리더 HP를 원작 수치라고 붙이지 않는 편이 정확하다.
- 소울 재산정과 색/총소울 지불은 위 재수록 FAQ와 2015 가이드로 보완했다. 소각으로 얻는 추가 자원, 장비 중첩, 장비 자체의 유지비, 모든 기술/영속 강화 예외는 확정하지 못했다. 원작 FAQ 재수록은 **유닛의** 빈 구슬 비용이 아이템/마법과 달리 매턴 유지비라고 명시하므로, 아이템/마법의 빈 구슬을 자동으로 유닛 유지비에 더하는 근거로 사용하지 않는다.
- 유니크 1장/스페셜 2장 같은 등급별 별도 구성 제한은 이번 공식 덱 가이드에서 찾지 못했다. 원작 제약이라고 임의로 추가하지 않는다. 팬 DB에는 카드별 `DeckLimit` 필드가 따로 있어 실제 카드 레코드의 제한과 기본 4장 규칙을 구분해야 한다.

## 근거 파일과 재사용 범위

`Artifacts/Validation/FmExpansion/Research/rules/*.json`은 실제 URL, 최종 URL, HTTP 상태, 조회 UTC, 원본 응답 크기/SHA-256, 디코딩 및 짧은 확인 인용만 보존한다. 전체 페이지나 원작 이미지를 이 조사 폴더에 복제하지 않았다. 팬 DB enum과 카드별 수치의 원본 기록은 별도 담당의 `Artifacts/Validation/FmExpansion/Research/database`를 따른다.

공개 열람이나 팬 DB 존재는 원작 소스·원화·음악의 배포 허락을 의미하지 않는다. 이 문서는 규칙/사실 확인의 출처이며, 코드나 이미지에 대한 재사용 라이선스 확인서가 아니다.
